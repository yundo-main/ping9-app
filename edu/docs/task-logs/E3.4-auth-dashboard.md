## 1. 목표와 완료 기준

- [x] 회원가입 페이지 — 이름·이메일·비밀번호(확인)·역할(학생/교사), Google 계속 버튼
- [x] 로그인 페이지 분리 — 목록의 인라인 패널 대신 `#/login` 전용 화면
- [x] 개인 대시보드 — 사용자 정보, 이어서 학습, 전체·단원별 진도, 레슨별 통과 표시
- [x] 공통 완료 조건

## 2. 진행 방식

1. `auth.ts` — `signUpWithEmail`에 `SignUpMeta{name, role}`를 받아 `user_metadata`(`display_name`, `role`)로 저장
2. `auth-page.tsx` (login-panel.tsx 대체) — mode prop으로 로그인/가입 한 컴포넌트, 비밀번호 확인·역할 라디오·서로 전환 링크
3. `dashboard.tsx` — 세션의 `user_metadata`에서 이름·역할을 꺼내 인사, 첫 미통과 레슨을 "이어서 학습" 카드로, 단원별 진도 바 + 레슨 목록(통과 표시·바로 가기)
4. 라우팅 — `#/login`/`#/signup`/`#/dashboard` 추가. 로그인 성공·비로그인 대시보드 접근은 각각 목록/로그인으로 보냄

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 역할·이름을 user_metadata에 | users 테이블(E4.2) 전에 프로필을 저장할 수 있는 유일한 자리 — 이관 시 같은 필드명을 쓴다 | public.users 즉시 생성 — Supabase 프로젝트가 아직 없다 |
| 대시보드 `#/dashboard` 분리 | 목록(공개 커리큘럼)과 개인 화면을 나눠 비로그인 사용자도 레슨을 볼 수 있다 | 로그인 후 목록 대체 — 공개 탐색이 죽는다 |
| 진도는 localStorage 유지 | E4.2에서 계정 DB로 옮기기 전까지 — 대시보드가 읽는 표면은 같다 | 지금 DB 연동 — env·프로젝트 미비 |

## 3. 결과

- 가입 → 로그인 → 대시보드 → 레슨의 개인 여정이 완성됐다
- 비로그인은 목록 탐색·레슨 플레이 가능, 대시보드만 로그인 필요
- typecheck·lint·build 통과

## 5. 계획과 달라진 점

- Supabase 프로젝트 미생성 상태라 실제 가입은 env(`VITE_SUPABASE_URL`/`ANON_KEY`)가 들어온 뒤에 동작한다 — env 없으면 패널에 "설정 전" 안내가 뜬다
- 가입 후 자동 로그인은 Supabase의 이메일 확인 설정에 따른다 — 확인이 켜져 있으면 메일 안내 문구가 뜬다
