## 1. 목표와 완료 기준

- [x] Supabase env 없이도 "게스트로 시작하기"로 로그인→대시보드 진입
- [x] 게스트 세션도 대시보드·진도가 동일하게 동작
- [x] 공통 완료 조건 (typecheck·build·check:secrets)

## 2. 진행 방식

1. `auth.ts` — 화면용 세션 타입 `EduSession{email, name, role, guest}` 도입. Supabase `Session`을 `mapSession`으로 변환해 UI가 Supabase 타입에 직접 붙지 않게 한다
2. 게스트 세션 — `signInAsGuest()`가 localStorage(`ping9-edu-guest`)에 표시하고 리스너에 통지. `onSession`은 Supabase 세션이 없으면 게스트를 돌려준다
3. `auth-page.tsx` — "게스트로 시작하기" 버튼. Supabase 미설정 화면에서도 보인다 (게스트는 env 불필요)
4. `dashboard.tsx` — `EduSession`으로 전환, 게스트면 "게스트 모드" 표시 + "가입하면 계정에 남습니다" 안내
5. `app.tsx` — 상단 바에 게스트는 "게스트" 표시

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `EduSession` 자체 타입 | 대시보드·앱이 Supabase `Session` 구조(user_metadata 등)에 묶이지 않고, 게스트라는 제2의 세션 종류를 같은 모양으로 다룬다 | Supabase Session에 캐스팅한 가짜 객체 — 필드가 어긋나고 타입을 속인다 |
| 게스트 진도도 같은 localStorage | 진도 저장(progress.ts)을 건드리지 않는다 — 계정 연동(E4.2) 전에는 어차피 브라우저 저장 | 게스트 전용 진도 — 중복 저장소 |

## 3. 결과

- env 없는 지금 배포에서도: 로그인 화면 → "게스트로 시작하기" → 게스트 대시보드 → 레슨·채점·진도 전부 동작
- 게스트 로그아웃은 게스트 표시 + Supabase 세션 둘 다 지운다
- typecheck·build·check:secrets 통과

## 4. 계획과 달라진 점

- 실제 계정 로그인은 여전히 Supabase 프로젝트 + env가 필요 — 게스트 모드는 그 사이 진입 장벽을 없애는 임시가 아니라, 계정 연동 후에도 "체험" 경로로 남는다
