## 2. 진행 방식

1. `docs/repo-structure.md` — 레이어 그림, 의존 규칙 매트릭스, 엔진 공유 방식(워크스페이스 소스 참조), 새 코드 배치 결정표, 향후 분리 옵션
2. `scripts/check-imports.mjs` — 추적 중인 소스 파일의 import specifier를 규칙 매트릭스로 검사. 패키지 이름이 아닌 상대 경로 우회(`../../packages/…`)도 잡는다
3. 규칙: edu→apps 금지, packages→apps·edu 금지, editor→`@tauri-apps/*` 금지, engine·shared→react·vite·tauri 금지(순수 TS), apps→edu 금지, apps/web→engine·shared 직접 금지(editor 경유)
4. `pnpm check` 맨 앞에 `check:imports`를 넣었다

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| ESLint 플러그인 대신 독립 스크립트 | 규칙이 "파일 위치 → 금지 패키지" 매트릭스라 no-restricted-imports 설정이 지저분해진다. 스크립트가 위반 사유(왜 금지인지)까지 한국어로 보인다 | eslint-plugin-boundaries — 의존 추가 + 설정 복잡도 |
| 상대 경로 탈출도 검사 | `../../packages/engine/src/x` 같은 우회가 exports 경계를 무력화한다 | 패키지 이름만 검사 — 우회가 남는다 |
| `docs/`의 `?raw` 픽스처 허용 | `vyos-guide.test.ts`가 가이드 문서를 raw로 읽는 의도된 탈출 | 예외 주석 방식 — 케이스가 하나라 규칙에 박았다 |
