## 1. 목표와 완료 기준

- [x] edu/app의 레슨 목록 — 단원별로 묶인 레슨 카드 (지금은 N1 레슨 1개)
- [x] 레슨 진입 시 `startDocument`를 시뮬레이터에 올리고 `@ping9/editor`의 `EditorApp`을 전체 화면으로 임베드
- [x] "채점하기"가 `grade(simulator, lesson)`을 돌려 조건별 ✓/✗과 피드백을 보여 준다
- [x] 공통 완료 조건 (lint, 타입 검사, 테스트, 빌드)

## 2. 진행 방식

1. `edu/app`에 `@ping9/editor`·`@ping9/edu-core` 워크스페이스 의존 추가
2. `lesson-player.tsx` — 진입 시 `simulator.load(lesson.startDocument)` 후 `EditorApp`을 렌더. editor의 `simulator` 싱글턴을 edu도 같이 써서 화면과 채점이 같은 상태를 본다
3. `lesson-list.tsx` + `check-label.ts` — 단원별 카드 목록과 Check→한 줄 목표 문자열 (과제 패널과 결과 목록이 공유)
4. `app.tsx` — 로그인 표시 아래 목록↔플레이어 전환 (URL 라우터는 아직, 뒤로가기는 "목록" 버튼)
5. 스타일 — `editor.css`를 먼저 import하고 edu의 `index.css`가 `body`의 `overflow:hidden`·`min-width`를 되돌린다. 플레이어에선 `.edu-player-sim .app { height: 100% }`로 본체의 `100vh`를 칸 크기로 오버라이드

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| EditorApp을 prop 없이 그대로 임베드 | `download`·`onActions` 없으면 브라우저 다운로드로 떨어져 웹에서 그대로 동작 — 학생이 만든 토폴로지도 내려받을 수 있다 | edu 전용 축소 화면 — 두 화면이 갈라지는 걸 E3.0이 막으려 했던 것과 모순 |
| 채점이 editor의 `simulator` 싱글턴을 침 | 레슨당 페이지에 editor가 하나뿐이라 싱글턴으로 충분, 인스턴스 주입 구조를 새로 만들 이유가 없다 | EditorApp에 simulator prop 추가 — 본체 코드를 건드려야 한다 |
| 레슨 전환 시 `key={lesson.id}`로 EditorApp 리마운트 | 화면 상태(선택·터미널·재생)가 레슨 사이에 새지 않게 전부 초기화 | 상태 리셋 함수 — EditorApp이 노출하지 않는 내부 상태라 리마운트가 정답 |

## 3. 결과

- `edu/app` 화면이 생겼다: 목록(단원 카드) → 플레이어(브리프 + 완료 조건 + EditorApp + 채점)
- 채점 결과는 조건별 `detail` 피드백과 함께 브리프 패널에 표시
- 예시 토폴로지 갤러리(스캐폴드 잔재)는 레슨 목록으로 대체
- `pnpm check` 통과 — edu/app typecheck·vite build 모두 editor 에셋 포함 성공

## 4. 검증 출력

```
edu/app    tsc --noEmit 통과 · vite build ✓ (editor css·png 에셋 번들 확인)
pnpm check lint + typecheck + test + build 전부 통과
```

## 5. 계획과 달라진 점

- `body { overflow: hidden }`(editor.css)이 edu 목록 화면의 스크롤을 죽여서 edu 쪽에서 되돌렸다 — 패키지 CSS는 그대로, 소비자가 화면별로 오버라이드하는 방식
- 진도 저장(DB)은 E4.2로 미뤄 로컬 상태만 쓴다
