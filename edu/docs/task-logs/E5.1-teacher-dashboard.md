## 2. 진행 방식

1. DB — `classes`(join_code)·`class_members`(display_name)·`assignments`·`attempts` 테이블 + RLS + `join_class(code)` RPC(security definer, 코드 검증을 서버에서)
2. RLS 재귀 함정 — 멤버 정책이 `classes`를, `classes` 정책이 멤버를 조회하며 무한 재귀 발생 → `is_class_teacher()`/`is_classmate()` security definer 함수로 정책 평가를 우회
3. `classes.ts` — 반·멤버·과제·진도표·막힘 통계 API. `recordAttempt`가 채점마다 실패 조건을 기록
4. `progress.ts` — 통과 저장을 `Map<lessonId, passed_at>`로 전환(옛 배열 형식 마이그레이션 포함) — 스트릭·"며칠 전" 표시의 데이터
5. 역할 분기 — `#/dashboard`에서 `teacher`면 `TeacherDashboard`, 아니면 `Dashboard`
6. 테마 — edu/index.css 전면 재작성(종이 팔레트·mono·pop 버튼·칩 좌측 색바·├─ 진도표 행), JetBrains Mono + Noto Sans KR 폰트

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 참가 = `join_class` RPC | 코드 일치 검증을 RLS가 아니라 security definer 함수에서 — classes 테이블 전체 노출 없이 코드로만 가입 | classes 전체 select 허용 — 모든 반이 코드와 함께 보임 |
| 멤버에 display_name 복사 | auth.users는 타인이 못 읽어 이름이 필요한 곳에 복사 저장 | profiles 테이블 — 아직 무겁다 (E5 후속 후보) |
| 막힘 분석 = attempts 집계 | grader의 실패 detail을 그대로 기록해 "어떤 조건에서 멈추는지"를 보여 준다 | 제출물 전체 저장 — 너무 무겁다 |

## 3. 결과

- 학생(`networked@naver.com`): 로그인 → 칩(진도·연속 학습·남은 과제) → 이어서 학습 → 과제 → 반 참가 → 단원별 진도표("며칠 전" 표시) → 이름 편집
- 교사(`meta4rism@gmail.com`): 로그인 → 반 만들기 → 참가 코드 → 반 선택 → 학생×레슨 진도표, 과제 내주기·완료 현황, 막힌 조건 상위 목록
- E2E 검증: 교사가 학생 진도 행을 읽음(RLS 정상), 학생 참가 RPC 동작
