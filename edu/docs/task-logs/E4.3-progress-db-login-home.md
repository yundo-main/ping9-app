## 2. 진행 방식

1. DB — Management API `/database/query`로 `public.progress(user_id, lesson_id, passed_at)` + RLS(본인 행만 select/insert). SQL은 대시보드 없이 API로 실행
2. `EduSession`에 `id`(auth.users uid) 추가 — DB 행의 `user_id`로 쓴다
3. `progress.ts` — `pushPassed`(통과 시 서버 upsert), `pullPassed`(로그인 시 서버 진도와 로컬 합집합 + 로컬 전용분을 서버로 업로드). 게스트는 여전히 localStorage만
4. 첫 화면 — 루트/알 수 없는 해시 → 세션 있으면 `#/dashboard`, 없으면 `AuthPage`(로그인). 목록은 `#/lessons`로 계속 열림
5. 로고 — `packages/editor` exports에 `./assets/*`를 열고 `@ping9/editor/assets/logo.png`를 import해 로그인 카드와 목록 헤더에 표시

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 진도 = 로컬∪서버 합집합 | 게스트로 하다가 가입해도 이전 통과가 날아가지 않고, 로컬 전용분을 로그인 때 서버로 올려 다음 기기에도 온다 | 서버 값으로 덮어쓰기 — 오프라인 통과가 사라짐 |
| `EduSession.id` 노출 | UI 계층이 DB 쓰기에 필요한 uid를 모르면 push가 안 됨 | Session 전체를 progress.ts로 넘기기 — Supabase 타입 결합 |
| editor exports `./assets/*` | 로고가 코어 자산이라 제품이 import하는 seam — 복사하면 두 벌이 된다 | edu에 logo.png 복사 |
