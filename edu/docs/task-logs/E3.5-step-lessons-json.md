## 1. 목표와 완료 기준

- [x] 레슨 스키마: `brief` 마크다운 덩어리 → `summary` + `steps[]`(단계별 안내, 선택 hint)
- [x] 레슨을 TS 코드에서 JSON 데이터로 — 콘텐츠·코드 분리 (교사 편집·다국어 확장 대비)
- [x] 플레이어에 단계 진행 UI — 이전/다음 버튼 + 단계 점 표시
- [x] 공통 완료 조건

## 2. 진행 방식

1. `lesson.ts` — `brief`를 `summary`(카드 한 줄) + `steps[{text, hint?}]`(min 1)로 교체. `defineLesson(input: unknown)`으로 넓혀 JSON을 스키마가 검증
2. `lessons/n1-first-ping.json` — 레슨을 데이터로 이전 (3단계: PC1 주소 → PC2 주소 → ping+ARP 관찰)
3. `lessons/index.ts` — JSON을 `defineLesson`으로 로드해 LESSONS 구성. 로드 시점에 토폴로지·check 검증은 그대로
4. `lesson-player.tsx` — `step` 상태, "단계 n/m" + 이전/다음 + 점 표시 + 접는 힌트. 채점·완료 조건은 그대로
5. `lesson-list.tsx` — 카드가 `summary`를 보인다

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 레슨을 JSON으로 | 코드와 콘텐츠를 갈라 교사 편집 UI·로케일 디렉터리(`ko/*.json`)로 늘리는 길을 연다 | TS 유지 — 타입 안전하지만 콘텐츠가 코드에 갇힌다 |
| `steps` 필드를 brief 대체 | 참고 사이트의 step-through 형식과 동일 — 긴 안내를 단계로 쪼개 진행감을 준다 | brief 유지 + 별도 steps — 중복 필드 |
| defineLesson을 `unknown`으로 | JSON import 타입은 리터럴 union에 안 맞아, 런타임 검증(zod)이 정답 — 이미 그 역할이다 | as 캐스팅 — 검증을 우회한다 |

## 3. 결과

- 레슨 = JSON 데이터 (스키마·토폴로지·check는 로드 시 zod가 여전히 걸러 준다)
- 플레이어 브리프가 단계별 안내 카드로 진화 — "단계 1/3" 네비게이션

- 참고 사이트처럼 다이어그램을 단계별로 보여 주는 대신, 우리의 "다이어그램 자리"는 임베디드 시뮬레이터라 단계는 안내 텍스트로 진행 — 다이어그램식 시각 진행은 후속 개선 후보
