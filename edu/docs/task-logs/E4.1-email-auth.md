## 1. 목표와 완료 기준

- [x] Supabase 클라이언트 모듈 (`auth.ts`) — env 없으면 비로그인으로 뜬다
- [x] 이메일·비밀번호 로그인/가입 폼 — Supabase 기본 Email provider로 바로 동작
- [x] Google 소셜 버튼 자리 — provider만 켜면 같은 코드가 동작한다
- [x] 세션 표시 — 로그인 중 이메일 + 로그아웃

## 2. 진행 방식

1. `@supabase/supabase-js` 추가 — anon key만 쓰는 클라이언트라 서버 코드 없이 SPA에서 바로 인증한다.
2. `auth.ts` — `signInWithEmail`/`signUpWithEmail`/`signInWithGoogle`/`signOut`/`onSession`. env(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)가 없으면 `supabase`가 undefined라 모든 화면이 비로그인 폴백으로 돈다 — 키 없이 개발 가능.
3. `login-panel.tsx` — 이메일+비밀번호 폼, "로그인"/"가입"/"Google로 로그인" 버튼. `app.tsx`는 세션을 받아 비로그인이면 패널, 로그인이면 이메일+로그아웃을 보인다.
4. `.env.example`에 필요한 env 두 개를 적었다. Vercel 대시보드에도 같은 두 개를 등록한다.

## 3. 결과와 검증

- `pnpm --filter @ping9/edu typecheck`·`build` 통과
- 실제 로그인 동작은 Supabase 프로젝트 생성(2단계) 후 env를 넣어야 확인 가능 — 지금은 비로그인 폴백이 검증됨

## 4. 계획과 달라진 점

- dev-plan의 인증 방식을 "Google만"에서 "이메일(기본) + Google(추후)"로 바꿨다 — 이메일은 Supabase가 기본으로 켜서 외부 설정 없이 바로 되기 때문이다.
- E4.1의 범위가 "Supabase 프로젝트 생성 + OAuth"에서 "클라이언트 로그인 기반"으로 옮겨졌다 — 프로젝트 생성·env·Google provider는 대시보드 작업으로 남아 있다.
