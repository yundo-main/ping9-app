## 1. 목표와 완료 기준

패킷 카드의 "헤더 구조" 보기를 Wireshark의 패킷 상세 창처럼 — 프로토콜별로 접히는 트리, 등폭 글꼴, 라이트 테마 — 로 바꾼다.

- [x] 프로토콜이 `<details>`로 접히는 트리 (Frame → Ethernet → IPv4 → TCP/ICMP…)
- [x] Wireshark식 줄 머리: "Ethernet II, Src: …, Dst: …", "Internet Protocol Version 4"
- [x] Wireshark식 필드 이름 (영문) + "이름: 값" 한 줄 표현
- [x] 라이트 테마 CSS (지금까지 `pkt-structure` 등에 CSS가 전혀 없어 스타일 없는 표였음)
- [x] 시뮬레이션이 생략한 필드는 값을 지어내지 않고 "—" 유지

## 2. 진행 방식

1. `apps/web/src/components/packet-structure.tsx` 전면 재작성:
   - `<section>` + `<table>` → `<details open>` + `<summary>` + 필드 줄
   - Wireshark처럼 모든 프로토콜을 Frame 아래 **형제 줄**로 나열 (안쪽 프로토콜을 겹겹이 넣지 않음)
   - 필드 이름을 Wireshark 영문 명칭으로 (Destination, Time to Live, Sequence Number …)
   - TCP 플래그는 실제 와이어값 포함 `0x012 (SYN-ACK)` 형식
   - 프로토콜 값 표기 방향 통일: `IPv4 (0x0800)`, `ICMP (1)` — 이름 먼저, 번호는 괄호
2. 카드가 `frameId`를 넘기면 맨 위에 "Frame N" 줄을 추가 (Wireshark의 Frame 줄)
3. `apps/web/src/styles/editor.css`에 `.pkt-structure`·`.ws-*` 스타일 신규 — 흰 배경, 옅은 파란 줄 머리, 호버 강조, 접힘 삼각형 `▸/▾`
4. 바이트 크기 열 제거 — Wireshark 상세 창은 바이트 열이 없고 육각 창이 따로 있다. 시험용 "해부도" 정보는 요약 보기가 이미 보여준다

## 3. 검증

- `packet-card.test.tsx`의 구조 보기 테스트 2개를 새 마크업으로 갱신:
  - `<td>` 표 단언 → `ws-fname`/`ws-fvalue` 스팬 단언
  - 체크섬 "—"·프로토콜 순서·TCP 플래그·HTTP 줄까지 유지
- 발견해 고친 것: 프레임의 TCP 플래그 문자열이 `PSH-ACK`(`-` 구분)인데 처음에 `+` 키로 매핑해 "—"가 나옴 → 맵 키를 `-`로 수정
- `pnpm vitest run packet-card.test.tsx` 13개 통과, `pnpm check` 전체 통과, `pnpm check:secrets` 통과

## 4. 계획과 달라진 점

- 필드의 "바이트" 열을 없앴다 — Wireshark 상세 창에 없는 열이고, 요약 보기가 이미 바이트 정보를 보여준다
- "페이로드 → IPv4" 포인터 줄 제거 — 형제 줄 나열로 바뀌어 불필요
