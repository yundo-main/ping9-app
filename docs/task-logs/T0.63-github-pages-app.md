## 1. 목표와 완료 기준

설치 없이 브라우저에서 PING9을 쓸 수 있게 한다 — main에 push하면 GitHub Pages로 랜딩+앱이 배포된다.

- [x] `https://yundo-main.github.io/ping9-app/` = 랜딩, `/app/` = 웹 앱
- [x] `main` push마다 자동 배포 (GitHub Actions → Pages)
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. 절대경로 자산을 `src/assets` import로 옮김 — Pages는 `/ping9-app/` 아래에 서빙돼 `/logo.png` 같은 절대 참조가 깨진다
2. `web-pages.yml` 워크플로: vite 빌드(`--base=/ping9-app/app/`) + docs 랜딩을 `site/`에 조립 → upload-pages-artifact → deploy-pages
3. Pages는 API로 `build_type=workflow` 전환 (기존 legacy `main:/docs` → Actions 배포)
4. 랜딩에 "웹으로 바로 열기" 버튼 (`app/` 상대 링크)

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 앱을 `/app/` 아래에 | 랜딩이 루트를 쓴다. base가 `/ping9-app/app/`라 자산 URL이 겹치지 않는다 | 앱을 루트에 — 랜딩을 다른 경로로 밀어야 함 |
| `src/assets` import | vite가 해시+base를 붙여 어떤 base에서도 맞다 | `public/` 유지+수작업 경로 — base마다 깨짐 |
| Actions 배포 (build_type=workflow) | docs/ 소스 방식으론 빌드 산출물을 못 올림 | dist를 docs/에 커밋 — 빌드 산출물이 저장소를 더럽힘 |
