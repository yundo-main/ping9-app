## 1. 목표와 완료 기준

- [x] `pnpm desktop:release` 한 명령으로 빌드 → `deploy/<버전>/`에 산출물이 모인다
- [x] `patch`/`minor`/`major`/`x.y.z` 인수로 버전을 올리면 `tauri.conf.json`과 `Cargo.toml`이 함께 바뀐다
- [x] 산출물은 OS에 상관없이 같은 이름 규칙(`PING9-<버전>-<OS>-<아치>.<확장자>`)을 갖는다
- [x] `manifest.json`에 버전, 빌드 시각, 파일별 sha256이 남는다
- [x] 산출물은 git에 커밋되지 않는다 (`deploy/*` ignore, `deploy/README.md`만 추적)
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절)
- [ ] 리뷰 — 팀원 검토 없이 main에 커밋했다

## 2. 진행 방식

1. Tauri가 만드는 산출물 위치(`src-tauri/target/release/bundle/`)는 OS마다 다른 이름(`PING9_0.1.0_aarch64.dmg`, `*-setup.exe`)을 쓴다 — 스크립트가 찾아서 일관된 이름으로 바꿔 `deploy/<버전>/`에 복사한다.
2. 버전의 원천은 `tauri.conf.json`으로 정하고, 스크립트가 `Cargo.toml`도 같이 고친다 — 두 곳이 어긋나면 앱의 "정보 보기"와 파일 이름이 갈라진다.
3. 0.1.0과 0.1.1(patch 올림)을 실제로 빌드해 두 버전이 나란히 쌓이는 것을 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 산출물은 git에 넣지 않는다 | 바이너리 수 MB가 커밋마다 쌓인다. 배포는 나중에 Release/아티팩트로 | 산출물 커밋 |
| 버전 원천은 `tauri.conf.json`, `Cargo.toml`은 스크립트가 동기화 | Tauri가 읽는 곳이 conf이고 Cargo는 바이너리 메타데이터에 쓰임 | 둘 다 손으로 관리 |
| `deploy/<버전>/` 아래에 `manifest.json`(sha256 포함) | 어떤 파일이 어느 버전인지, 손상 없이 받았는지 확인하는 재료 | 해시 없이 파일만 |

## 3. 변경 내용

| 파일 | 변경 |
|---|---|
| `scripts/desktop-release.mjs` | **신규.** 버전 올리기(`patch`·`minor`·`major`·`x.y.z`), `tauri build` 실행, `deploy/<버전>/` 수집·이름 변경, `manifest.json` 생성 |
| `deploy/README.md` | **신규.** 디렉터리 구조와 사용법 |
| `package.json` | `desktop:release` 스크립트 |
| `.gitignore` | `deploy/*` 무시, `deploy/README.md`는 추적 |
| `apps/web/src-tauri/tauri.conf.json`, `Cargo.toml`, `Cargo.lock` | 버전 0.1.0 → 0.1.1 (검증 겸 올림) |

## 4. 결과와 검증

```text
$ pnpm desktop:release          # 0.1.0 빌드
deploy/0.1.0/
  PING9-0.1.0-macos-arm64.dmg  (9.0 MB)
  manifest.json  (버전·sha256 기록)

$ pnpm desktop:release patch    # 0.1.0 → 0.1.1, tauri.conf.json+Cargo.toml 동기화
버전 0.1.1으로 올림 (tauri.conf.json, Cargo.toml)
deploy/0.1.1/
  PING9-0.1.1-macos-arm64.dmg  (9.0 MB)
  manifest.json
```

- `manifest.json` 예: `{"version": "0.1.1", "platform": "darwin/arm64", "files": [{"file": "...", "bytes": 9418517, "sha256": "c4b7…"}]}`
- `git check-ignore`로 dmg가 무시됨을 확인, `deploy/`에는 README만 staged
- `pnpm check:secrets` 통과 (파일 859개)
- `pnpm check`는 T17.1 커밋에서 통과했고 이번 변경은 스크립트·설정·문서라 다시 실행하지 않음 — mjs는 `test:scripts` 대상 테스트가 없음

## 6. 계획과 달라진 점

- **T17.1 로그에서 예고한 번호가 밀렸다.** T17.1은 T17.2를 "GitHub Actions matrix 빌드"로 예고했는데, 이 작업(로컬 deploy 디렉터리)이 먼저 필요해 T17.2가 됐다. CI matrix는 T17.3, 서명은 T17.4로 밀렸다.
- **팀원 검토 없이 main에 커밋** (T17.1과 같음).

## 7. 남은 일과 다음 Task에 전할 것

- **T17.3**: GitHub Actions matrix — 이 스크립트를 runner에서 그대로 돌리면 `deploy/<버전>/`을 아티팩트로 올릴 수 있다. Windows의 `nsis/*-setup.exe` 수집 규칙은 이미 들어 있다.
- **T17.4**: 서명 — mac은 Developer ID + notarize, Windows는 인증서. 미서명 dmg는 Gatekeeper 경고가 뜬다.
- 스크립트는 mac 전용 경로가 아니다 — Windows runner에서도 동작해야 한다 (검증은 T17.3에서).
- `tauri.conf.json`의 `version`은 이제 스크립트로만 올린다. 손으로 고치면 `Cargo.toml`과 어긋난다.
