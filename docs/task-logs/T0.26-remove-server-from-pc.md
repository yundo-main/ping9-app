# T0.26 PC에서 서버 기능 제거 (계획에 없는 새 ID. T0.25 후속)

## 1. 무엇을 했는가

T0.25가 서버 장비를 독립시킨 뒤 PC 쪽에 남아 있던 서버 기능을 전부 걷어냈다. PC는 이제 서비스를 듣지도, 필터를 적용하지도 않는 순수 클라이언트다.

- **`PcConfig`에서 서버 칸 제거**: `services`, `dnsRecords`, `filter`, `os: "server"`를 뺐다. 서버 칸은 `ServerConfig`에만 있다.
- **`pc/*` 서비스 명령 삭제**: `pc/set-service`, `pc/add-dns-record`, `pc/remove-dns-record`를 Command 합집합과 리듀서에서 지웠다. 옛 명령을 보내면 `PC_NOT_SERVER`가 아니라 `UNKNOWN_COMMAND`다.
- **`device/add`의 `os`는 `OsKind`**: `server` 값은 더는 받지 않는다. 다만 옛 호출(`kind: "pc" + os: "server"`)이 경계 밖에서 들어와도 서버를 만들도록 실행시 검사는 남겼다.
- **`pc/set-os`의 `os`도 `OsKind`**: 마찬가지로 실행시에는 `"server"`를 받아 서버로 바꾸는 옛 경로를 유지한다 (저장된 명령 호환).
- **PcModel의 서버 훅 제거**: `filter`, `listening`, `respond`를 뺐다. `TransportHost`의 두 훅은 선택(`?`)이 됐고, `Ipv4Host`의 `filter`는 원래 선택이라 PC는 넘기지 않는다. `devices/pc/services.ts`와 `reducer/pc-services.ts` 파일을 지웠다.
- **PC의 자기 접속**: 자기 주소·127.x로 보낸 서비스 요청은 PC가 듣는 서비스가 없으므로 항상 거절이다.
- **공유 헬퍼 재대상**: `servicesOf`, `dnsRecordsOf`, `checkPcServices`, `filterOf`, `hasActiveFilter`, `checkPcFilter`가 `ServerConfig`를 받는다. `filterOf`는 더는 `os === "server"`를 보지 않고 칸만 본다.
- **화면**: `OsChoice`는 `OS_KINDS`(Windows/Linux)만, 방패 배지·필터 위치 표시는 `kind === "server"`일 때만.

## 2. 진행 방식

1. shared: `PcConfig`·스키마에서 서버 칸을 빼고, 서비스·필터 헬퍼의 인자를 `ServerConfig`로 바꿨다. `pc/*` 서비스 명령 삭제.
2. engine: PcModel 훅 제거, `devices/pc/services.ts`·`reducer/pc-services.ts` 삭제, transport 훅을 선택으로.
3. web: `OsChoice`를 `OS_KINDS`로, 필터 검사를 server kind로 좁힘.
4. 테스트 갱신: 명령 수, 옛 명령은 `UNKNOWN_COMMAND`, 필터·서비스 검사는 server 장비 기준 fixture로.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `os: "server"`를 옛 명령 경로에만 남김 | 저장된 문서·명령과의 호환. 형식은 좁히고 실행시 검사로 받는다 | 명령 호환까지 끊기 — 옛 파일을 못 여는 것보다 나쁘다 |
| TransportHost의 `listening`/`respond`를 선택으로 | PC는 클라이언트로 계속 쓰고(요청 송신), 서버 훅만 뺀다 | PC에서 TransportHost를 아예 빼기 — 요청 경로를 새로 짜야 해 과하다 |
| `PC_NOT_SERVER` 코드·메시지 유지 | `firewall/*`·`server/*`에 kind 검사가 먼저 있어 사실상 안 나지만, 방어 경로로 둠 | 코드 삭제 — 어긋난 문서를 수작업으로 넣을 경로가 남는다 |

## 3. 검증

- `pnpm check` 전체 통과: shared 469, engine 1849, web 626 테스트 + lint + typecheck + build.

## 4. 계획과 달라진 점

T0.25 로그에 "`pc/*` 서비스 명령은 PC에서 거절로 남음"이라고 적었지만, 이 Task에서 명령 자체를 지워 `UNKNOWN_COMMAND`가 됐다.
