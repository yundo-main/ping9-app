## 1. 목표와 완료 기준

- [x] 클라우드를 두 번 누르거나 인스펙터 버튼으로 내부 구조 창이 열린다 (콘솔 대신)
- [x] 창에는 4개 내부 에지 라우터의 K4 메시, 포트별 /30 링크·붙은 장비, 배운 RIP 경로가 보인다
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. `cloud-inside-dialog.tsx`를 새로 만들었다 — help-dialog와 같은 `.confirm-backdrop` + `role="dialog"` 패턴, × 버튼과 바깥 누르기로 닫는다.
2. 창 본문은 SVG 한 장 — 구름 안에 내부 라우터 4개(`R0`~`R3`)를 원형으로 놓고 K4 메시(점선)로 연결, 각 라우터에서 바깥으로 포트 꼬리 선이 뻗어 Port 이름·/30 링크 주소·붙은 장비 이름을 보여 준다. 케이블이 없는 포트는 회색 점선으로 그린다.
3. `view.routes`의 `R` 경로를 포트별로 집계해 꼬리 옆에 초록색으로 적는다 — "이 포트 너머로 어떤 네트워크를 배웠나".
4. `app.tsx`의 `openTerminal`에서 `kind === "cloud"`면 터미널 대신 이 창을 연다 — 캔버스 두 번 누르기와 인스펙터 버튼 둘 다 이 경로를 탄다. 인스펙터 버튼 글자도 클라우드일 땐 "내부 구조 보기"로 바꿨다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 콘솔 대신 내부 구조 창으로 연결 | 클라우드는 CLI가 없어 "두 번 누르면 열린다" 경로가 비어 있었다 | 별도 메뉴/버튼 |
| 4개 내부 라우터 K4 메시로 시각화 | 4개 포트가 각각 에지 라우터 역할, 포트끼리는 풀메시로 라우팅된다는 개념 모델 | 진짜 내부 토폴로지(구현은 포트별 독립이지만 개념 모델로 표시) |
