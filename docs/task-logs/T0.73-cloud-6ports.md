## 2. 진행 방식

1. `PORT_NAMES.cloud`를 여섯 개로 늘렸다 — FastEthernet 이름은 되돌리고 Port 이름을 유지한다. /30 링크망은 `1.0.0.{4i}` 규칙이라 Port5까지 `1.0.0.20/30`이 배정된다.
2. 우선경로는 기존 RIP 규칙 그대로다 — `#routes`가 prefix당 경로 하나만 들고, 더 낮은 메트릭이거나 같은 다음 홉에서 메트릭이 바뀔 때만 갈아 끼운다. 같은 메트릭의 나중 광고는 무시되므로 먼저 배운 경로가 우선된다. 이 동작을 테스트로 못 박았다.
3. 내부 구조 창은 노드 좌표·꼬리·간선을 하드코딩하던 것을 버리고, 포트 수만큼 타원 둘레에 등간격으로 노드를 놓는 동적 원형 배치로 바꿨다 — 위(-90°)에서 시작해 시계 방향. 배운 네트워크는 상대 장비 상자 안에 초록 줄로 쌓는다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 원형 동적 배치 | 포트 수가 바뀔 때마다 좌표를 다시 잡는 것보다 N개 노드를 타원 둘레에 놓는 쪽이 유지보수가 낫다 | K3/K4 하드코딩 좌표 |
| 우선경로는 표를 갈라서 보여 주지 않는다 | RIP 모듈이 prefix당 하나만 저장해 대안 경로가 아예 테이블에 없다 — 실제 라우터와 같다 | 대안 경로 별도 표시 |
