## 1. 목표와 완료 기준

- [x] `kind: "l3switch"` 장비 추가 — 스위치의 L2 전달 위에 L3 라우팅을 얹는다
- [x] SVI(`interface vlan <id>`)로 VLAN 간 라우팅, `no switchport`로 라우티드 포트
- [x] `ip routing` 토글, `ip route` 정적 경로, RIP 경로 교환
- [x] IOS 콘솔, Inspector(인터페이스·MAC·라우팅 표), 팔레트·아이콘
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. **구성**: `L3SwitchConfig = SwitchConfig + ipRouting + interfaces + staticRoutes + rip`. `interfaces`의 키는 `Vlan<id>`(SVI) 또는 `routed: true`인 포트 이름. 포트 이름은 `FastEthernet0/1`~`0/8`
2. **모델** (`devices/l3switch/`):
   - `switchForward`에 `ports`(후보 제한)와 `consumeMacs`(내 MAC으로 온 프레임 소비) 훅을 넣고 `egress`를 내보냈다 — 스위치 전달 로직을 그대로 재사용
   - 라우티드 포트로 들어온 프레임은 L2를 건너뛰고 라우터 수신 경로로 간다
   - L2 포트로 들어와 목적지 MAC이 **시스템 MAC**(모든 L3 인터페이스가 첫 포트 MAC 하나를 나눠 씀)이면 그 VLAN의 SVI가 받는다
   - 브로드캐스트는 L2 플러딩하면서도 CPU 사본이 간다 — 내 SVI를 묻는 ARP 요청과 RIP 멀티캐스트는 L3가 답한다
   - L3 나가기는 SVI의 VLAN 안에서 L2로 나간다 — MAC 표에 있으면 그 포트, 없으면 VLAN의 모든 포트로 플러딩
3. **RipModule 일반화**: 라우터 포트 결합을 `RipHost` 콜백(interfaces·macOf·linkOf·send)으로 바꿔 라우터와 L3 스위치가 함께 쓴다
4. **CLI**: `cli/l3switch/`를 새로 두고, 스위치 명령 묶음의 `devices`를 넓혀 재사용하고(`vlan`, `switchport`, `show vlan brief` 등), `routeCommands(devices)`·`ripCommands(devices)`를 팩토리로 만들어 라우터 정의를 재사용했다
5. **reducer**: 겹치는 명령(`interface/set-ip`·`route/*`·`rip/*`)은 기존 처리기에 l3switch 분기를 얹고, l3 전용(`l3switch/svi`·`set-routed`·`set-ip-routing` 등 4개)은 `reducer/l3switch.ts`에 뒀다

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 시스템 MAC 하나 | 실제 Catalyst SVI도 장비 MAC 하나를 쓴다. SVI별 MAC은 불필요한 복잡함 | SVI별 MAC 파생 |
| `switchForward` 훅 확장 | L2 전달 규칙(MAC 학습·trunk 태그·차단)을 두 벌 만들면 어긋난다 | L2 전달 코드 복제 |
| 라우터 명령을 devices 팩토리로 재사용 | `ip route`·`network` 문법이 같아 중복 정의는 드리프트가 난다 | l3switch용 정의 복제 |
| `switchport`를 routed 포트에 치면 L2로 복귀 | 실제 IOS의 `switchport` 의미. 별도 오류보다 자연스럽다 | routed 포트에서는 거부 |
| SVI 상태 = VLAN 캐리어 | SVI는 물리 링크가 없다 — 그 VLAN에 켜진 L2 포트가 있어야 up | 링크와 무관하게 항상 up |

## 4. 계획과 달라진 점

- RIP 모듈을 라우터 전용에서 `RipHost` 인터페이스 기반으로 리팩터했다 — 계획에는 "재사용"만 있었고 방식은 구현 중 정했다
- `show running-config`는 스위치 렌더러를 재사용하지 않고 L3 전용(`l3RunningConfigLines`)을 뒀다 — L2만 나오는 출력보다 전체 출력이 낫다
- 정규화에서 라우티드 포트는 `mode: "access"`를 들고 있다 — `L3SwitchPortConfig`가 `SwitchPortConfig`를 확장해 `mode`가 필수라서, routed 포트에서는 무시되는 잔재다
