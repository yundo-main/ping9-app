# T0.28 apps/api 자리표시 제거와 개발 의존성 갱신

## 1. 무엇을 했는가

- `apps/api` 패키지를 지웠다. T2.1.1(Hono 앱) 계획의 자리표시로 `index.ts` 상수 하나와 테스트 둘뿐이었고, T0.24의 데스크톱 배포 전환으로 웹 서버를 만들 일이 사라졌다. 어떤 패키지·CI·스크립트도 `@ping9/api`를 참조하지 않음을 확인한 뒤 지웠다.
- 개발 의존성의 patch·minor를 올렸다: eslint 10.15.0, typescript-eslint 8.73.0, vitest 5.1.1, fast-check 4.11.0, vite 8.3.8, @vitejs/plugin-react 6.3.0, @tauri-apps/cli 2.12.6.

## 2. 진행 방식

1. `grep`으로 `@ping9/api` 참조가 자기 자신뿐인지 확인 → `rm -rf apps/api` → `pnpm install`로 잠금파일 정리.
2. 카탈로그(`pnpm-workspace.yaml`)의 버전을 올리고 `pnpm install` → `pnpm-lock.yaml`의 해석 버전을 확인.
3. `pnpm check` 전체 실행.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 패키지 통째 삭제 | 데스크톱 전환으로 HTTP 서버가 없고, 부활이 필요하면 이력에서 되살리면 된다 | 자리표시 유지 — 죽은 코드가 계속 남는다 |
| typescript 7·@types/node 26 제외 | 메이버전 점프와 node 24 불일치 — 실습용 안정성을 위해 보류 | 전부 최신으로 |

## 3. 검증

- `pnpm check` 전체 통과: shared 469 · engine 1858 · web 628 테스트 + lint + typecheck + build (api 분은 패키지와 함께 사라짐).
- `pnpm-lock.yaml`에 새 버전이 해석됐다.

## 4. 계획과 달라진 점

T2.1.1(Hono API)은 계획 문서에 남아 있지만 데스크톱 앱으로 가면서 실행할 일이 없다. 계획 문서는 팀 합의 후에 고치므로 여기서는 코드만 정리했다.

## 5. 남은 일

- 계획 문서의 T2.1.1을 실제 상태(보류·폐기)로 정리하는 것은 팀 합의가 필요하다.
