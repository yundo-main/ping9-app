# T0.55 — LB 계층 이름 표기 + 플라이아웃 호버 동작

## 진행 방식과 결과

사용자 요청: LB 항목에 L4/L7 이름을 달고, 마우스오버가 없으면 플라이아웃 메뉴를 원복(닫기)한다.

- `components/palette.tsx`: 스위치 플라이아웃의 LB 항목 라벨을 `LB` → `L4/L7 LB`로
  바꿔 형제 항목(L1 Hub · L2 Switch · L3 Switch)의 계층 표기와 맞췄다.
- 같은 파일: 스위치·라우터 그룹이 마우스오버로 열리고 마우스가 나가면 닫히게 했다.
  단순 `onMouseEnter/Leave`가 아니라 `pointerType === "mouse"`로 걸러서 —
  터치의 탭은 합성 `mouseenter`+`click`이 연달아 와 첫 탭이 열고 바로 닫히는 버그를
  피한다. 터치·펜은 `onPointerDown`(비-마우스) 토글, 키보드는 `onClick`의
  `detail === 0` 토글로 처리한다. 마우스 사용자의 여닫기는 호버가 전담한다.
- 추가 게이트: `full`(장비 한도)이거나 `dragCancel !== "idle"`(새 장비 끌기 중
  취소 안내 상태)이면 호버로 열리지 않는다.
- `styles/editor.css`: `.switch-flyout`이 `left: calc(100% + 8px)`라 그룹과
  플라이아웃 사이 8px의 틈을 지나는 순간 mouseleave가 발동해 플라이아웃에
  닿기 전에 닫혔다 → `::before` 투명 다리로 틈을 메웠다.
- 툴팁 문구를 "눌러 …" → "올리거나 눌러 …"로 갱신(두 그룹).
- 라우터 그룹에도 같은 동작을 적용 — 같은 `switch-flyout` 패턴이라 두 그룹의
  동작이 갈리면 어색해서다.

## 검증

`pnpm check` 범위 중 web 기준: `tsc -b` 통과, `vitest run` 647/647 통과.
SSR 테스트는 포인터 이벤트를 흉내 못 해 호버 경로는 수동 확인 필요 — 새 테스트 없음.

## 계획과 달라진 점

- 계획 문서에 없는 새 Task ID(T0.55)로 진행.
- 라벨 표기는 사용자 표기 `L4/L7`를 그대로 썼다 — 아이콘 배지의 `L4·7`·툴팁의
  `L4·L7`(가운뎃점 표기)와는 의도적으로 별개 표기다.
- 마우스 클릭으로는 플라이아웃이 토글되지 않는다(호버가 담당). 키보드·터치는
  기존처럼 토글된다.
