## 1. 목표와 완료 기준

- [x] 라우터 속성 패널의 "라우터 CLI 형식"에서 `Linux · ip/sysctl 명령어`를 고를 수 있다
- [x] 리눅스 형식의 라우터 콘솔은 `root@<이름>:~#` 프롬프트의 단일 셸이다 (모드·세션 없음)
- [x] `ip addr [show]`, `ip addr add|del <CIDR> dev <ethN>`로 인터페이스 주소를 보고 바꾼다
- [x] `ip link [show]`, `ip link set <ethN> up|down`으로 포트를 켜고 끈다. IOS의 `GigabitEthernet0/N`이 `eth0`~`eth3`에 대응한다
- [x] `ip route [show]`, `ip route add|del <네트워크>|default via <다음 주소>`로 정적 경로를 본다
- [x] `sysctl net.ipv4.ip_forward`로 전달 여부를 보고, `sysctl net.ipv4.ip_forward=0`로 끄면 지나가는 패킷이 `IP_FORWARD_DISABLED`로 버려진다
- [x] `ping`, `traceroute`, `ip neigh`·`arp`, `hostname`이 동작한다
- [x] 기존 IOS·VyOS 형식과 PC 콘솔은 그대로 동작한다

## 2. 진행 방식

1. 제안서([docs/proposals/linux-native-router.md](../proposals/linux-native-router.md))대로 `shared` → `engine` → `web` 순서로 고쳤다.
2. `shared`: `RouterConfig.cliStyle`에 `"linux"`, `ipForward?: boolean` 칸, `router/set-ip-forward` Command, `IP_FORWARD_DISABLED` 폐기 사유를 더했다. `ipForward`는 켜짐(기본값)이면 문서에 남기지 않는다 (`normalizeRouterConfig`).
3. `engine`: 콘솔 분기(`console.ts`)에 `cliStyle === "linux"` 갈래를 넣고, 리눅스 명령 묶음(`cli/router/linux-commands.ts`)을 만들었다. 출력 형식은 Linux PC 쪽의 출력 도우미(`linuxPingLines` 등)를 썼다.
4. 전달 차단은 라우터 모델(`router-model.ts`)에서 자기 것 판별 **뒤**, 경로 조회 **앞**에 뒀다 — 자기 주소로 온 패킷은 `ip_forward`와 무관하게 받는 실제 리눅스와 같다.
5. `web`: 형식 선택에 Linux 항목을 넣고, `IP_FORWARD_DISABLED`의 이벤트·원인 문구를 넣었다.
6. `cli/router/linux-console.test.ts`를 새로 쓰고 `pnpm check`를 돌렸다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `ip_forward` 기본값은 **켜짐** | 라우터는 놓자마자 전달해야 기존 토폴로지가 깨지지 않는다. 끄는 실습은 `sysctl ...=0`으로 한다 | 실제 리눅스 기본값 0: 기존 문서의 라우터가 전부 멈춘다 |
| `ipForward`가 false면 경로 조회 없이 바로 `IP_FORWARD_DISABLED` | 실제 커널도 forward를 꺼놓은 호스트는 라우팅 없이 버린다. 실패 원인이 곧바로 보인다 | 경로 조회 뒤에 버리기 |
| `cliStyle`을 `linux`로 바꿔도 `vyos`·`vpnMode`는 지우지 않는다 | 형식을 잠깐 바꿨다 돌아와도 설정이 남는다. VyOS로 바꿀 때만 `vpnMode`를 지우는 기존 규칙도 그대로 | 전환 때 관련 없는 설정 비우기 |
| 리눅스 출력은 PC 쪽 도우미를 쓰고, `ip` 결과 묘사만 새로 썼다 | PC 리눅스와 라우터 리눅스의 `ping`·`traceroute`·`arp` 출력은 같아야 한다 | 라우터용 출력을 따로 만들기 |

### 새 테스트 (`linux-console.test.ts`, 10개)

- 프롬프트 `root@R1:~#`, `ip addr`가 `eth0`~`eth3`을 보이고 `GigabitEthernet`가 나오지 않음
- `ip addr add|del`이 문서의 인터페이스 주소를 바꾸고 `validateDocument`를 통과함
- `ip link set up|down`이 `adminUp`을 바꾼다. 케이블이 없으면 `NO-CARRIER`로 보임 (실제와 같이 관리 상태만 켜짐)
- `ip route add|del`이 `staticRoutes`를 바꾼다. 링크가 없으면 경로가 비활성이라 `ip route`는 빈 출력, 살아 있는 실습 랩에서는 connected·static 줄을 보임
- `sysctl net.ipv4.ip_forward`의 조회·설정, 없는 키(`cannot stat /proc/sys/bogus/key`)와 잘못된 값
- `hostname`으로 장비 이름과 프롬프트가 함께 바뀜
- `?` 도움말과 Tab 완성
- **전달 차단**: 랩 토폴로지에서 `sysctl net.ipv4.ip_forward=0` → PC 간 ping이 끊기고 추적에 `IP_FORWARD_DISABLED`가 남음 → `=1`로 복구하면 다시 통함

## 6. 계획과 달라진 점

- **팀원 검토 없이 병합했다.** 작업 규칙 3은 Pull Request와 다른 팀원 한 명의 검토를 요구한다. 담당이 main에 직접 병합을 지시해, `check` 통과만 확인하고 넣었다.
- **Task ID가 계획에 없다.** 제안서([docs/proposals/linux-native-router.md](../proposals/linux-native-router.md))에서 `T16.x`를 새로 썼다. 프로젝트 계획 04-tasks에는 없는 번호다.
- **`ip_forward` 기본값이 제안서와 다르다.** 제안서는 기본값을 팀 판단 사항으로 남겼다. 기존 문서 호환을 위해 **켜짐**으로 정했다. 실제 리눅스의 기본값(0)과 다른 점은 수업에서 `sysctl` 실습으로 다뤄야 한다.
- 제안서의 T16.1 범위(`ip`·`sysctl`·`ping`·`traceroute`·`hostname`) 외에 `ip neigh`·`arp`·`clear`도 넣었다. 출력 도우미가 이미 있어 추가 비용이 거의 없었다.

## 7. 남은 일과 다음 Task에 전할 것

- **T16.2**: 라우터용 `iptables` (filter + nat 테이블 저장·보기, `-t` 표시). 서버 PC의 `iptables` 해석기(`cli/pc/iptables*.ts`)를 참고한다.
- **T16.3**: NAT 실제 동작 (MASQUERADE/SNAT/DNAT + conntrack). 전달 경로(`router-model.ts`의 `#decision` 앞뒤)에 변환 단계가 들어간다.
- **T16.4**: 라우터 iptables의 화면 패널과 `-t` 표시.
- `ip_forward`가 꺼져 있을 때 **자기 주소로 온 패킷과 라우터가 내는 패킷(ping, RIP)은 영향이 없다.** RIP 경로 교환은 계속 돈다 — 수업에서 "전달만 꺼진다"는 점을 분명히 해야 한다.
- 리눅스 형식에서도 IOS 형식과 같은 `staticRoutes`·`interfaces` 문서를 쓴다. 형식을 바꿔도 설정이 그대로 보인다는 뜻 — `ip addr`에서 ethN ↔ `show ip interface brief`에서 Gi0/N이 같은 값이다.
- `ip route`는 **활성 경로만** 보인다 (링크 다운이면 숨김). 저장된 정적 경로는 문서에 남아 링크가 살아나면 다시 보인다 — 실제 커널의 동작과 같은 의도다.
