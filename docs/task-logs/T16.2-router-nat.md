# T16.2 Router NAT (ip nat inside/outside + 동적 주소 변환)

## 1. 무엇을 했는가

Router 인터페이스에 `nat` 역할(inside/outside)을 주고, `outside`로 나가는 패킷의 출발지를 그 인터페이스 주소로 바꾸는 동적 NAT(PAT)를 구현했다.

- **설정**: `RouterInterfaceConfig.nat?: "inside" | "outside"`. 명령 `interface/set-nat` (router 전용). IOS 콘솔의 `ip nat inside`·`ip nat outside`·`no ip nat …`(config-if)가 이 명령을 보낸다. `running-config`에 ` ip nat …` 줄이 남는다.
- **SNAT (나감)**: `nat outside`인 출구로 전달되는 패킷은 출발지를 인터페이스 IP로 바꾼다. TCP·UDP는 출발지 논리 포트도 49152번대의 `natPort`로 바꾼다(PAT). ICMP echo는 sequence를 그대로 쓴다. 같은 (proto, 안쪽주소, 안쪽포트, 상대주소, 상대포트)는 바인딩을 재사용한다.
- **DNAT (들어옴)**: outside 인터페이스에 도착해 목적지가 그 인터페이스 IP인 패킷은 바인딩과 맞으면 안쪽 호스트로 되돌린다(TCP·UDP는 natPort→insidePort 역변환). 바인딩이 없으면 라우터 자신이 받는 패킷 — 바깥에서 시작한 연결은 열리지 않는다 (가정용 공유기와 같다).
- **ICMP 오류**: TTL 만료·도달 불가는 인용된 패킷으로 바인딩을 찾아 안쪽으로 되돌린다. 인용 안의 출발지도 NAT 주소→안쪽 주소로 고쳐 받는 호스트가 자기 패킷으로 알아본다.
- **이벤트**: `NAT_TRANSLATED` (방향, 안쪽 주소, 바깥 주소, 상대 주소, 프로토콜·포트)를 전달 경로에 남긴다 — 패킷 추적에서 주소 변환이 눈에 보인다.

## 2. 진행 방식

1. shared: `nat` 칸, 명령, 스키마, 이벤트 코드. `normalizeRouterConfig`가 칸을 버리지 않게 고쳤다(처음에 빠져서 설정이 안 남았다).
2. engine: `interface/set-nat` 리듀서 → `RouterModel`에 `#snat`·`#dnat`와 바인딩 테이블 3개(정확한 바깥 키·안쪽 재사용 키·ICMP 오류용 느슨한 색인).
3. cli: `defineCommand` 패턴 그대로 `ip nat` 네 줄.
4. 테스트: `staticRoutingLabDocument` 랩에서 실제 ping → NAT 이벤트 양방향 확인.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| Cisco식 인터페이스 역할 표시 | `ip nat inside/outside`가 교재 표준. inside 표시는 문서용(동작에 영향 없음) | Linux `iptables -t nat` — 라우터 콘솔이 IOS식이라 톤이 안 맞음 |
| 포트도 바꾸는 PAT | 두 안쪽 호스트가 같은 출발지 포트를 써도 구별된다 — 실제 NAT 동작과 같다 | 출발지만 바꾸기 — 포트 충돌 시 응답이 엇갈린다 |
| 변환 테이블은 모델의 런타임 상태 | ARP 테이블처럼 Document에 저장하지 않는다. 세션이 닿는 동안만 연결로 본다 | 만료 타이머 — 교육용 범위를 넘는다 |
| `nat`는 라우터 인터페이스 칸 | `interface/set-*` 계열과 저장 위치가 같다 | RouterConfig 최상위 `nat` 객체 |

## 4. 계획과 달라진 점

T16.2는 원래 "라우터 iptables" 계열로 잡혀 있었으나 NAT만 구현했다. 라우터의 iptables 필터(`filterOf` 계열)는 범위 밖이다.

### 후속 구현 (같은 Task의 이어짐)

- **`show ip nat translations`** — `RuntimeAccess.natTranslations`과 `RouterModel.natTranslations()`를 추가해 콘솔이 런타임 바인딩 테이블을 읽는다. 표는 `Pro / Inside local / Inside global / Outside` 네 열이다.
- **정적 NAT** — `RouterConfig.natStatics`와 `router/set-static-nat`(`outsideIp` null = 삭제). IOS `ip nat inside source static <inside> <outside>`·`no` 형태, running-config에 남는다. 바깥 주소로 온 패킷은 바인딩 없이 안쪽 호스트에 고정 대응된다(포트 그대로). 스키마(`schema.ts`)에도 추가해야 저장된다 — 처음에 빠뜨려 dispatch가 통과해도 문서에 안 남았다.
- **Inspector** — 인터페이스 행에 `nat inside/outside` 배지, 정적 NAT 대응 목록 섹션.
- **linux 스타일** — `iptables -t nat -A/-D POSTROUTING -o ethN -j MASQUERADE`가 `interface/set-nat`에 대응. `-L`/`-S POSTROUTING` 조회.
- **vyos 스타일** — `nat source rule N outbound-interface ethN` + `translation address masquerade` 두 잎이 함께 있어야 그 인터페이스가 outside. `settingsOf`/`compile` 양방향 변환. inside 표시와 정적 NAT는 VyOS·linux에서 표현하지 않는다(ios만).
