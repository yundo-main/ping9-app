# T0.53 — 토폴로지 실행취소·재실행

## 한 일

Document 편집을 되돌리는 실행취소(⌘Z)·재실행(⇧⌘Z)을 만들었다. Edit 메뉴의 기본 Undo·Redo(웹뷰 텍스트 편집용)를 지우고 앱 동작으로 바꿨다.

- `engine/simulator.ts`: `past`/`future` 두 스택에 직전 Document를 넣는다 — Document는 얼어 있는 불변 객체라 통째로 보관해도 안전하다. dispatch 성공 때마다 이전 문서를 `past`에 쌓고 `future`를 지운다(최대 100개). `undo()`/`redo()`는 dispatch와 같은 후처리를 탄다: 바뀐 쪽의 ARP·MAC 항목 비우기, RIP이 있으면 경로 교환 1회. `load()`는 기록을 비운다 — 가져오기·새 토폴로지 이전으로는 못 돌아간다.
- `lib.rs`: Edit의 기본 "Undo"/"Redo" 항목을 "실행 취소"(⌘Z)·"재실행"(⇧⌘Z)으로 교체, `menu-undo`/`menu-redo` 이벤트.
- `app.tsx`: 이벤트를 `simulator.undo()`/`redo()`에 연결. 메뉴가 없는 개발용 브라우저용으로 ⌘/Ctrl+Z 키 핸들러도 뒀다(입력창·터미널에 초점이 있으면 건너뛴다). document 효과에 범위 선택 정리를 추가 — 되돌려 사라진 장비·케이블이 묶음에 남지 않는다(장비 선택·터미널·케이블 도구는 기존 효과가 이미 정리한다).

## 계획과 달라진 점·주의점

- 기본 Undo/Redo를 덮어써서 입력창의 텍스트 되돌리기는 메뉴로 안 된다(브라우저용 키 핸들러는 입력창을 건너뛰어 거기선 기존 동작). 이 앱의 입력칸은 짧아 재입력 비용이 작다고 판단했다.
- CLI 세션(현재 모드)은 되돌리지 않는다 — 열린 콘솔은 지금 문서 기준으로 동작한다.
- 진행 중인 ping 재생·이벤트 추적은 되돌리지 않는다(Trace 목록은 그대로다).
