## 2. 진행 방식

1. 배포 방식을 비교(Python pywebview, Tauri, Electron, 로컬 서버+브라우저)하고 담당이 **Tauri**를 골랐다. 이유: 결과물이 ~10MB로 가볍고, Rust "코드"를 쓸 필요 없이 툴체인만 필요하며, 프로젝트 스택(pnpm)과 맞다.
2. `@tauri-apps/cli` 2.12.5를 catalog에 추가하고 `apps/web`의 devDependency로 넣었다 (2.12.6은 공개된 지 7일이 안 되어 한 단계 아래를 골랐다).
3. `pnpm tauri init --ci`로 `apps/web/src-tauri/`를 만들었다. `frontendDist: "../dist"`, `devUrl: http://localhost:5173`, `beforeBuildCommand: "pnpm build"`.
4. 식별자 `com.tauri.dev` → `com.ping9.desktop`, 창 크기 800×600 → 1280×800으로 고쳤다.
5. 아이콘은 `src/assets/panel-penguin.png`(1350×880)를 880×880 정사각으로 잘라 `pnpm tauri icon`으로 모든 크기를 생성했다.
6. `pnpm tauri build`로 번들을 만들고 `.app`을 열어 프로세스가 살아 있음을 확인했다.
7. eslint가 `src-tauri/target` 안의 생성 JS를 훑어 오류가 났다 → ignore에 `**/src-tauri/target/**`와 `**/src-tauri/gen/**`를 추가했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| Tauri | 결과물 ~10MB, OS 웹뷰 재사용, Rust 코드 불필요 | Electron(~150MB), pywebview(Python 툴체인 추가) |
| 껍데기는 `apps/web/src-tauri`에 둔다 | 프론트엔드가 `apps/web`이라 같은 패키지에 두는 것이 Tauri 관례 | 별도 `apps/desktop` 패키지: 빌드 경로가 더 복잡해짐 |
| `version: 0.1.0`, 식별자 `com.ping9.desktop` | 개발 단계. 출시 때 버전·서명 정책과 함께 다시 정한다 | — |

## 6. 계획과 달라진 점

- **팀원 검토 없이 main에 직접 커밋했다.** 작업 규칙 3은 `feat/` 브랜치 + PR + 팀원 검토를 요구한다. 담당이 main만 쓰기로 정해(이전 작업에서 브랜치를 모두 지움) 검토 없이 넣었다.
- **Task ID가 계획에 없다.** 04-tasks에 없는 `T17.x`를 썼다. 데스크톱 배포는 원래 계획(Vercel 웹 배포)에 없는 새 방향이다 — 팀 합의가 필요하다.
- **아이콘이 기본 Tauri 아이콘이 아니다.** `panel-penguin.png`를 잘라 만들었다. 정식 아이콘은 디자인 합의가 필요하다.

## 7. 남은 일과 다음 Task에 전할 것

- **T17.2**: GitHub Actions matrix로 `windows-latest` + `macos-latest` 빌드 → `.exe`(nsis)와 `.dmg` 아티팩트. `tauri-apps/tauri-action` 사용.
- **T17.3**: 서명. macOS는 Apple Developer ID + notarization, Windows는 코드 서명 인증서. 없으면 Gatekeeper/SmartScreen 경고를 우회하는 안내가 필요하다.
- `tauri.conf.json`의 `version`은 0.1.0 고정 — 출시 태그 정책과 연동할 것.
- `pnpm tauri dev`로는 콘솔 로그가 보이는 개발 모드로 띄울 수 있다 (자동으로 `pnpm dev`도 함께 돈다).
- Windows에서는 WebView2가 필요하다 — 오래된 교실 PC는 설치본의 bootstrapper가 같이 깔아준다.
- 서명 없이 배포하면 macOS에서 "확인되지 않은 개발자" 경고 — 실습실 배포라면 허용 방법을 안내 문서에 적어야 한다.
