## 1. 목표와 완료 기준

랜딩 페이지에 별도 "히스토리" 섹션을 만들어 Task 작업 기록을 표시한다.

- [x] 히스토리 섹션 — ID + 제목, 각 행이 해당 로그 문서(GitHub)로 링크
- [x] 새 로그가 추가돼도 랜딩을 손으로 고치지 않아도 되는 자동 생성

## 2. 진행 방식

1. `scripts/update-landing-history.mjs` — `docs/task-logs/README.md`의 표 행을 파싱해
   `docs/index.html`의 `<!--HISTORY:BEGIN/END-->` 사이를 다시 쓰는 스크립트
   - 제목 끝의 "(계획에 없는 새 ID)" 꼬리표는 표시에서 뗀다
   - 최근 것이 위로 오게 역순
2. 랜딩에 `.history` 스타일(표, 모노 ID 열, 호버)과 섹션 추가
3. `web-pages.yml`의 Assemble 단계에서 `site/index.html`에 같은 스크립트를 돌려
   배포 산출물이 항상 최신 목록을 갖게 한다 — 로컬 미리보기는 수동 실행으로 갱신

## 3. 검증

- `node scripts/update-landing-history.mjs` → 155행 생성, 링크·역순 확인
- `pnpm check:secrets` 통과
- push 후 web-pages 워크플로가 site/index.html을 재생성해 배포
