# T17.3 GitHub Actions matrix 데스크톱 빌드와 버저닝 (계획에 없는 새 ID)

## 1. 무엇을 했는가

`desktop-release` 워크플로(`.github/workflows/desktop-release.yml`)를 만들었다. Actions 탭에서 수동으로 실행하면 버전 올리기→태그·릴리스→macOS·Windows 병렬 빌드→릴리스 첨부까지 간다.

- **버저닝**: 시맨틱 버전으로 **1.0.0부터** 시작한다. `tauri.conf.json`과 `Cargo.toml`을 1.0.0으로 올렸다. 워크플로 인수는 `patch | minor | major | x.y.z` — 로컬 스크립트의 버전 인수와 같다.
- **`bump` 잡**: `scripts/desktop-release.mjs --bump-only`로 두 버전 파일을 올리고, 봇 커밋(`Bump version to x.y.z`)을 `main`에, 태그 `v<x.y.z>`를, `gh release create`로 릴리스를 만든다. 태그가 이미 있으면 실패한다.
- **`build` 잡**: `macos-latest`·`windows-latest` 매트릭스. 그 태그를 checkout해 `node scripts/desktop-release.mjs`를 돌리면 runner OS의 산출물이 `deploy/<버전>/`에 모인다 (mac→dmg, Windows→nsis exe·msi). `gh release upload`로 릴리스에 붙인다.
- 스크립트에 `--bump-only`를 추가했다: 버전 파일만 쓰고 빌드하지 않는다. CI의 범프 잡과 로컬에서 쓴다.

## 2. 진행 방식

1. 스크립트의 버전 로직을 재사용하려고 `--bump-only` 플래그를 넣었다 (범프 잡이 빌드하지 않게).
2. 워크플로는 bump → build(matrix) 2잡. 산출물은 워크플로 아티팩트가 아니라 `gh release upload`로 릴리스에 바로 붙인다 — 별도 release 잡과 upload-artifact 액션이 필요 없다.
3. 액션은 ci.yml과 같은 커밋 해시로 고정했다 (SEC-27). 릴리스·업로드는 runner에 있는 `gh` CLI를 써서 추가 액션이 없다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 수동 dispatch + 버전 인수 | 언제 배포할지는 사람이 정한다. 태그 트리거는 로컬에서 태그를 만드는 절차가 따로 필요하다 | `v*` 태그 push 트리거 |
| 봇 커밋을 main에 바로 push | 버전 파일이 저장소와 릴리스에서 일치해야 한다. 혼자 개발 규칙상 PR 없이 main에 커밋한다 | 버전을 릴리스 때만 runner에서 바꾸기 — 저장소 버전이 어긋난다 |
| `gh` CLI로 릴리스 | runner에 내장. softprops/action-gh-release를 고정 해시로 또 관리할 필요가 없다 | release 전용 액션 |
| `contents: write` 최소 범위 | 태그·릴리스·커밋에 필요. ci.yml의 read 권한과는 목적이 다르다 | — |

## 3. 검증

- `node scripts/desktop-release.mjs --bump-only 1.0.0` → `NEW_VERSION=1.0.0`, 두 파일만 바뀜 확인.
- `node scripts/check-secrets.mjs` 통과.
- 실제 매트릭스 빌드는 첫 dispatch(`1.0.0`) 때 검증한다.

## 4. 계획과 달라진 점

T17.2 로그의 예고대로 matrix CI를 T17.3으로 진행했다. 다만 산출물을 "워크플로 아티팩트"가 아니라 "GitHub Release 첨부"로 바꿨다 — 사용자가 받는 물건은 릴리스 페이지가 맞다.

## 5. 남은 일

- **T17.4 서명**: 무서명 dmg·exe는 Gatekeeper·SmartScreen 경고가 뜬다. mac은 Developer ID + notarize(`TAURI_SIGNING_PRIVATE_KEY` 등 secrets), Windows는 인증서가 필요하다.
- 첫 실행 후 Windows 산출물(nsis/msi) 수집이 제대로 되는지 확인해야 한다 — 스크립트의 Windows 경로는 아직 실제로 안 돌아봤다.
