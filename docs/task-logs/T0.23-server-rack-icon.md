## 1. 목표와 완료 기준

- [x] 서버는 **진짜 장비 종류** `kind: "server"`다 — PC + `os: "server"` 조합이 아니다. 놓으면 `Server1`로 이름이 붙는다
- [x] 서버 아이콘은 이글루가 아니라 세워 둔 랙이다. 방패 배지(필터 규칙)도 그대로 단다
- [x] 장비 목록에 Server 버튼이 따로 있고, 끌어 놓으면 `device/add` 한 번으로 서버가 놓인다
- [x] 터미널 칩·속성 패널 칩·화면 낭독 라벨이 "Server"다
- [x] `pc/set-os`로 PC ↔ Server를 오갈 수 있다 — kind가 통째로 바뀐다
- [x] 옛 문서(`kind: "pc"` + `os: "server"`)는 불러올 때 `kind: "server"`로 올라간다 (`migrateDocument`)

## 2. 진행 방식

1. 처음엔 목록 버튼만 가상 종류(`PaletteKind = DeviceKind | "server"`)로 넓히고 놓을 때 `device/add pc` + `pc/set-os server` 두 명령을 보냈다 — 스키마를 안 건드리는 빠른 안.
2. 담당이 "별도 서버 디바이스"를 요구해 **스키마에 `kind: "server"`를 추가**하는 쪽으로 다시 구현했다. T0.21의 `firewall → router` 마이그레이션 선례를 따랐다.
3. 핵심 결정: 서버 장비도 `config.os === "server"`를 저장한다 — `osOf`, `isServer`, 서비스·필터 같은 **구성만 읽는 헬퍼를 하나도 바꾸지 않기 위해**. 불변식(`kind: "server"` ⇔ `os: "server"`)은 생성·`pc/set-os`·마이그레이션 세 곳에서 지킨다.
4. kind를 읽는 경계는 새 헬퍼로 갈았다: `isPcKind(kind)`(kind 값), `isPcLikeDevice(device)`(장비 객체를 `PcLikeDevice`로 좁힘 — kind 검사만으로는 TS가 `config`를 좁히지 못한다).
5. `pc/set-os`는 kind를 통째로 전환한다: PC에서 `server`를 고르면 `kind: "server"`, 서버에서 `windows`/`linux`를 고르면 `kind: "pc"`로. 링크와 IP 구성은 그대로 남는다.
6. CLI 명령의 `devices: ["pc"]` 필터는 `["pc", "server"]`로 — 콘솔은 서버에도 PC 콘솔(linux)을 연다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `kind: "server"` + `config.os: "server"` 중복 저장 | `osOf`·`isServer` 등 config만 받는 헬퍼 ~20곳을 안 건드림. 두 형태를 정규화하는 것보다 단순 | os를 빼고 모든 헬퍼를 장비 단위로 교체 (호출지 ~20곳 수정, 하나 빠뜨리면 서버가 Windows PC처럼 동작) |
| 마이그레이션으로 옛 `pc + os server` → `kind: server` | 한 형태만 남겨 칩·이름·검증이 갈라지지 않게 | 두 형태 공존 허용 (칩이 "PC"로 보이는 옛 서버가 남음) |
| `pc/set-os`가 kind를 전환 | 속성 패널 OS 라디오로 PC↔Server 왕복이 그대로 동작 | `pc`에서만 허용하고 서버는 재생성 요구 |
| `schemaVersion`은 1 유지 | 옛 형식을 새 버전이 읽는 마이그레이션이라 버전 올릴 필요 없음. 새 형식을 옛 버전이 못 읽는 것은 알려진 제약 | schemaVersion 2 (불필요하게 큰 작업) |

## 6. 계획과 달라진 점

- 팀원 검토 없이 main에 커밋.
- 최초 기록은 "문서 스키마를 손대지 않는다"였으나, 담당 요청으로 `kind: "server"`를 스키마에 추가했다.
- **호환 메모**: 이 커밋 이후 내보낸 파일의 서버는 `kind: "server"`다. 이 형식을 읽는 것은 이 버전부터 — 그 전 버전은 `kind: "server"`를 모른다. 옛 파일(`pc` + `os: "server"`)은 이 버전에서 열면 자동으로 `kind: "server"`로 올라간다.
- `DeviceView`의 `kind`는 서버도 `"pc"`다 (뷰 구조가 같으므로 구분하지 않음).
