## 1. 목표와 완료 기준

- [x] `LbFrontend.mode: "http"` — L4 DNAT가 아니라 LB가 TCP를 끝내는 프록시 (HAProxy `mode http`)
- [x] `LbBackend.pathPrefix` — 요청 경로 접두가 맞는 백엔드만 후보가 된다 (HAProxy `path_beg`/`use_backend` 모사)
- [x] 백엔드는 LB의 나가는 인터페이스 IP를 출발지로 본다 — 진짜 프록시의 주소 관계
- [x] `L7_REQUEST_ROUTED` 이벤트, Inspector 모드 선택·경로 입력, `haproxy -c` 출력
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. **L4 버그 수정 (선행)**: `#accept`가 SYN만 받아 바인딩이 있는 연결의 ACK·요청 세그먼트도 PORT_CLOSED로 버리던 것을 고쳤다 — 기존 바인딩을 먼저 찾고, 새 바인딩은 SYN에만 만든다. 이전 테스트가 SYN까지만 봐서 못 잡은 회귀다
2. **L7 연결 상태**: `#l7ByClient`(클라이언트 다리)·`#l7ByBackend`(백엔드 다리) 두 색인. 클라이언트 SYN에는 LB가 직접 SYN-ACK으로 답하고, PSH-ACK+요청이 오면 백엔드 다리 SYN을 연다
3. **경로 선택**: `GET <경로>`의 두 번째 토큰을 뗀다. `pathPrefix`가 맞는 백엔드가 있으면 그 풀에서, 없으면 접두 없는 백엔드 풀에서 가중 라운드로빈 — 풀별로 커서를 따로 둔다. 두 풀이 다 비면 `503 Service Unavailable`로 직접 답한다
4. **`#sendSegment`**: 프록시가 직접 만드는 세그먼트(SYN-ACK·ACK·요청·응답)를 경로 조회+ARP로 보내는 도우미. 이벤트는 `TCP_SEGMENT_SENT`·`SERVICE_*_SENT/RECEIVED` 기존 코드를 재사용하고 선택 순간만 `L7_REQUEST_ROUTED`를 기록한다
5. **화면**: Inspector에 프런트엔드마다 `L4 TCP`/`L7 HTTP` 선택을 두고, http일 때 백엔드 추가 양식에 "경로 /api (선택)" 칸을 연다. `haproxy -c`·`cat /etc/haproxy/haproxy.cfg`는 `server` 줄에 `path /api`를 보여준다

## 3. 검증

- `pnpm check` 전체 통과 — shared 470 · engine 1894(+4) · web 640
- 새 L7 테스트 4개: LB가 직접 SYN-ACK, `/api` 접두 라우팅, 접두 없는 경로의 기본 풀, 왕복 중계(백엔드는 LB IP를 출발지로 봄 → 응답은 VIP로 되돌아감)

## 4. 계획과 달라진 점

- 테스트 토폴로지를 고쳤다 — `eth1`에 링크 두 개는 물리적으로 불가능해 백엔드 세그먼트에 허브를 끼웠다. FakeEnd도 실제 NIC처럼 내 MAC·브로드캐스트가 아닌 프레임과 남의 ARP 요청을 무시하게 했다
- 경로 규칙은 `LbFrontend.pathRules`(별도 규칙 목록) 대신 백엔드에 `pathPrefix` 필드를 붙이는 더 평평한 모양으로 갔다 — Inspector에서 한 열로 편집되고 풀 계산이 간단하다
- `validate`는 `pathPrefix`가 `/`로 시작하는지만 본다 — tcp 모드에서 달려 있어도 무해하므로 허용한다
