## 1. 목표와 완료 기준

- [x] 패킷 카드에 `요약 | 헤더 구조` 라디오 토글을 둔다
- [x] 구조 보기는 실제 헤더 해부도대로 필드·바이트·값 표를 계층별로 펼친다
- [x] 시뮬레이션이 갖지 않는 필드(체크섬·순서 번호·길이)는 "—"로 두고 값을 지어내지 않는다

## 2. 진행 방식

1. **`packet-structure.tsx`**: 프레임을 바깥 Ethernet부터 안쪽으로 계층 섹션으로 푼다 — Ethernet II 14B(+802.1Q 4B), ARP 28B, IPv4 20B, GRE 4B/ESP 8B + 안쪽 IPv4·ICMP, TCP 20B, UDP 8B, ICMP, RIP, 응용 데이터
2. 각 섹션은 (필드 이름, 바이트 수, 값) 표 + "▼ 페이로드 → 다음 계층" 꼬리. EtherType·프로토콜 번호는 실제 규격값을 프레임 내용에서 유도한다 (ARP 0x0806, IPv4 0x0800, ICMP 1, TCP 6, UDP 17, GRE 47, ESP 50)
3. 카드 머리의 `role="radiogroup"` 라디오로 보기를 고른다 — 요약(기존 상자)이 기본값
4. CSS: `.pkt-mode` 토글, `.pkt-sec`/`.pkt-fields` 표 스타일 — 기존 카드 색 체계 재사용

## 3. 검증

- `pnpm check` 전체 통과 — web 642(+2: ICMP 프레임 구조 순서·생략 필드 `—`, TCP+HTTP 구조)
- 생략 필드가 `—`인 것과 EtherType/프로토콜 번호가 규격값인 것을 테스트로 잠갔다

## 4. 계획과 달라진 점

- 사용자가 라디오 버튼을 허용해 카드 내 라디오 토글로 구현했다 — 별도 모드 탭이 아니라 카드 안에서 전환된다
