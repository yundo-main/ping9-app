## 1. 목표와 완료 기준

T0.24에서 걷어낸 Vercel 배포를 다시 쓸 수 있게 저장소 설정을 둔다 — 데스크톱 앱이 주 배포인 것은 그대로, 웹으로도 열 수 있게.

- [x] 루트 `vercel.json`이 모노레포에서 `apps/web` 빌드를 서빙한다
- [x] SPA 딥링크를 위해 모든 경로를 `index.html`로 돌린다
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

- `installCommand`: `pnpm install --frozen-lockfile` — Vercel이 `packageManager`·`pnpm-lock.yaml`로 pnpm을 알아본다
- `buildCommand`: `pnpm --filter @ping9/web build` — shared·engine은 `exports`가 `src/*.ts`를 가리켜 vite가 소스에서 직접 컴파일한다. 선행 빌드 불필요
- `outputDirectory`: `apps/web/dist`
- `framework: null` — "Other" 정적 산출. 프레임워크 감지의 기본 명령이 개입하지 않게
- `rewrites` — 클라이언트 라우터는 없지만 딥링크·새로고침에 안전한 SPA 규칙

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 루트 vercel.json + outputDirectory | 대시보드 Root Directory를 `apps/web`로 두면 workspace 의존 처리가 Vercel 측 감지에 의존한다 | Root Directory 설정 방식 — 설정이 대시보드에만 남아 저장소에서 안 보임 |
