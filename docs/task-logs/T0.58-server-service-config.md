## 1. 목표와 완료 기준

서버마다 "서비스별 기능"을 고를 수 있게 한다 — 사용자 선택지 중 "서버별 서비스 설정"으로 결정.

- [x] 서버별로 HTTP·FTP가 내놓는 파일 목록(이름+내용)을 편집할 수 있다
- [x] 서버별로 NTP stratum을 정할 수 있다
- [x] `curl http(s)://`·`curl ftp://`가 설정된 파일을 내놓고, `ntpdate -q`가 설정된 계층을 답한다
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. `ServerConfig`에 `files?: ServerFile[]`·`ntpStratum?: number`를 얹고 zod 스키마·정규화·한도(`maxServerFiles: 32`)를 함께 둠
2. `serverFilesOf(config, name)` 헬퍼를 shared에 둬 "설정이 없으면 기본 두 파일(index.html·readme.txt)" 규칙을 엔진과 웹이 공유
3. 명령은 DNS 레코드와 달리 델타가 아니라 통째 치환(`server/set-files`) — 목록이 작아 단순하다
4. 인스펙터는 SSH 계정·DNS 레코드와 같은 추가·삭제 폼 패턴을 따름

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `files`는 통째 치환 명령 하나 | DNS 레코드처럼 add/remove 두 명령보다 중복 이름·한도 검사가 한 곳에서 끝난다 | `server/add-file`·`server/remove-file` 분리 |
| NTP 응답에 `server stratum N`을 그대로 담고 클라이언트가 파싱 | 서버 응답 형식은 이미 있어 클라이언트만 고치면 됐다 | ServiceOutcome에 별도 stratum 필드 |
| 파일 내용 4096자 제한 (입력 maxLength) | 문서 크기를 키우지 않으면서 실습용 페이지엔 충분 | 제한 없음 |

## 6. 계획과 달라진 점

계획에 없는 새 기능. `serverFilesOf(config, name)`은 서버 이름이 바뀌면 기본 index.html 본문의 `<title>`도 바뀌는 기존 동작을 보존하려고 이름을 인수로 받는다.
