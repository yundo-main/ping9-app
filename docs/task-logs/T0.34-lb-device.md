## 2. 진행 방식

1. **구성**: `LbConfig`는 `RouterConfig`와 같은 모양의 `interfaces`·`staticRoutes`에 `frontends`를 얹었다. `LbFrontend`의 `mode`는 `"tcp"`만 구현했고 `"http"`는 L7(T0.35)을 위해 타입에만 남겼다
2. **모델** (`devices/lb/lb-model.ts`): 라우터의 IPv4 수신 경로(NO_IP·TTL·ICMP echo) 위에 L4 계층을 얹었다
   - `mode: "tcp"` 프런트엔드의 listenPort로 SYN이 오면 바인딩(`#byClient`/`#byBackend` 양방향 색인)을 만들고, weight만큼 벌인 배열을 커서로 돌리는 가중 라운드로빈으로 백엔드를 고른다
   - 요청은 목적지를 백엔드로, 응답은 출발지를 VIP로 재작성해 전달한다 — 클라이언트는 VIP만 본다
   - `LB_BACKEND_SELECTED` 사유 코드로 선택 이벤트를 기록한다
3. **connectedRoutes 일반화**: 라우팅 테이블의 직접 연결 경로가 `PORT_NAMES.router`에 묶여 있던 것을 넘겨받은 포트 뷰로 바꿨다 — LB의 `eth0`/`eth1`도 connected 경로가 잡힌다. 라우터는 같은 목록을 넘기므로 동작이 같다
4. **CLI** (`cli/lb/`): 리눅스 네이티브. 라우터의 linux 스타일과 같은 형태의 `ip` 명령 + `haproxy -c`·`cat /etc/haproxy/haproxy.cfg`로 프런트엔드 목록을 본다. 콘솔은 `root@LB1:~#` 프롬프트
5. **reducer**: `interface/set-ip`·`route/*` 같은 겹치는 명령은 기존 처리기에 lb 분기, `lb/set-frontends`만 `reducer/lb.ts`에 새로 뒀다
6. **화면**: Inspector의 `LbSettings`가 listenPort·백엔드(ip/port/weight)를 편집하고 목록 통째로 `lb/set-frontends`를 dispatch한다. 아이콘은 추 하나에서 세 갈래로 나뉘는 모양(보라)

## 4. 계획과 달라진 점

- **토폴로지 조건**: 백엔드는 LB 뒤 세그먼트에 두고 게이트웨이를 LB로 잡아야 한다 — 응답이 LB를 지나야 역변환이 된다. Inspector 안내 문구에 적었다
- `shortPortName`에 `eth`→`e` 규칙 추가 — `eth0`이 `e0`으로 줄어든다
- `mode: "http"`는 이번 Task에 없다 — L7 프록시는 T0.35에서 구현한다
- 도움말 대화상자의 장비 목록 갱신은 메뉴얼 작업(T0.35 뒤)에서 L3 스위치와 함께 한다
