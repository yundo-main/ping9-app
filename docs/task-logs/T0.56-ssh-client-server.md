## 1. 목표와 완료 기준

- [x] PC(Windows·Linux)와 Server 콘솔에서 `ssh <IP>` / `ssh -l <사용자> <IP>` / `ssh <사용자>@<IP>`로 서버·라우터에 접속
- [x] 비밀번호 프롬프트와 실제 계정 검증 — 틀리면 "Permission denied", 3번 틀리면 끊김
- [x] 접속 뒤 프롬프트가 원격 장비 것으로 바뀌고 명령이 원격 콘솔에 위임된다. `exit`·`logout`으로 복귀
- [x] 서버: 인스펙터에서 SSH 서비스 토글과 계정 추가·삭제 (새 서버는 ssh 켜짐, 기본 계정 `user`/`ping9`)
- [x] 라우터 IOS: `username <이름> secret <암호>` · `ip domain-name <이름>` · `crypto key generate rsa` · `show ip ssh`
- [x] 라우터 VyOS: `set service ssh` · `set system login user <이름> authentication plaintext-password <암호>`
- [x] 라우터 Linux: `useradd`·`systemctl start ssh` → `systemctl` 파이프라인에 연결
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드, 리뷰)

## 2. 진행 방식

1. shared — `ServiceKind`에 `"ssh"`(tcp/22) 추가. `ServerConfig`에 `sshAccounts` 필드와 `server/add-ssh-account`·`server/remove-ssh-account` 명령. `RouterConfig`에 `ssh?: { domainName?, keyGenerated, users[] }` 필드와 zod 스키마. `normalizeRouterConfig`가 새 필드를 떨구던 것을 보존으로 수정(실패 테스트로 발견)
2. 엔진 런타임 — `router-model.ts`가 자신에게 오는 모든 TCP를 port-unreachable로 답하던 것을, `config.ssh`가 있으면 tcp/22를 받아들이도록 확장. 서버는 기존 서비스 경로를 타고 ssh 응답은 배너 한 줄
3. 엔진 CLI — `cli/ssh.ts`에 `ssh` 클라이언트 명령(매개변수 파싱, `runtime.exchange`로 TCP/22 연결만 선으로 그림)과 세션 상태 `sshPending`(비밀번호 대기)·`ssh`(접속 중). `console.ts`가 이 상태를 보고 프롬프트를 만들고 명령을 원격 장비의 콘솔에 위임. `exit`/`logout`은 기본 모드에서만 끊고 config 모드에서는 모드를 닫는다 — 원격 세션이 라우터의 저장된 `CliSession`을 이어 받으므로 실제처럼 모드가 유지된다
4. 라우터 설정 — IOS용 `ssh-commands.ts`(username/ip domain-name/crypto key generate rsa/show ip ssh), Linux용 `ssh-linux-commands.ts`(useradd + systemctl), VyOS는 `vyos/config.ts`에 규칙 2줄. `running-config.ts`에 ssh 섹션 출력
5. 화면 — 인스펙터 서비스 구역에 `SSH tcp/22` 스위치와 계정 편집 목록

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| SSH 핸드셰이크·키 교환을 패킷으로 그리지 않고 TCP 연결 + 배너만 시뮬레이션 | HTTPS 때와 같은 단순화 — 계층 표시가 목적 | 암호화 과정까지 프레임으로 구현 (범위 과다) |
| 비밀번호·계정을 패킷이 아니라 대상 장비 설정에서 직접 검증 | 교환 프레임에 자격증명을 실으면 모델이 어색해짐 | 인증 요청/응답 메시지를 ServiceRequest로 추가 |
| 원격 세션 = 원격 장비의 저장된 `CliSession`을 그대로 이어 받기 | 라우터에서 `end` 전에 나가면 다음 접속에 모드가 유지되는 실제 동작을 재현 | 접속마다 user 모드로 초기화 (더 예측 가능하지만 덜 사실적) |
| `noAbbrev` 플래그를 CommandDefinition에 추가 | `ss`가 `ssh`의 줄임으로 먹혀 "ss: command not found"가 깨짐. `ssh`를 줄임 불가로 | 파서 전체 약어 규칙 변경 (영향 과다) |

## 7. 남은 일과 다음 Task에 전할 것

- SSH 키 교환·호스트 키 확인(처음 접속 시 yes/no)은 시뮬레이션하지 않는다 — 배너 + 비밀번호만
- 라우터의 SSH 포트는 고정 tcp/22 — `ip ssh port` 같은 설정은 없다
- `normalize*Config` 계열에 새 config 필드를 넣으면 반드시 보존 목록에도 추가해야 한다 — 안 하면 인스펙터에서 보이지만 CLI에서 안 잡힌다
