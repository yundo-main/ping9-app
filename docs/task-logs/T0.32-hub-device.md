## 1. 목표와 완료 기준

- [x] 스위치를 단순화한 허브 장비 종류(`kind: "hub"`) 추가 — VLAN도 MAC 테이블도 없다
- [x] 들어온 포트를 빼고 링크가 있는 모든 포트로 프레임을 보낸다 (플러딩만, 전달 학습 없음)
- [x] 팔레트·아이콘·이름·이벤트 문구까지 화면에서 쓸 수 있다
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드)

## 2. 진행 방식

1. shared에 `hub` 종류·`HubConfig`(빈 칸)·`HubView`·스키마를 만들고, 포트 이름은 `Port0`~`Port7`로 했다 — Packet Tracer 허브처럼 프로토콜 이름이 없는 단순한 이름
2. `HubModel`을 새로 만들었다 — `DeviceModel`을 구현하고, 받음을 기록한 뒤 링크가 있는 나머지 포트로 `transmit`한다. `portViewsOf`를 써서 링크 없는 포트에는 이벤트도 남기지 않는다
3. 이벤트 사유는 `FRAME_FLOODED`를 재쓰지 않고 `HUB_FLOODED`를 새로 둘랐다 — 그 사유에는 VLAN 매개변수가 있는데 허브에는 VLAN이 없기 때문
4. 콘솔은 정의를 주지 않았다 — `DEFINITIONS_BY_KIND`가 `Partial`이라 모든 명령이 `CLI_UNKNOWN_COMMAND`가 되고, 프롬프트는 `HUB1>`가 된다

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `HUB_FLOODED` 사유 신설 | 허브에는 VLAN이 없어 `FRAME_FLOODED`(vlan 매개변수 필수)에 억지 값을 넣기 싫었다 | `vlan: 1`을 채워 재사용 |
| 포트 이름 `Port0`~`Port7` | 허브는 1계층이라 Ethernet 이름을 붙일 이유가 없고, 스위치(Fa)·PC(Eth)와 겹치지 않는다 | `Ethernet0~7` (PC와 같은 이름) |
| `shortPortName`에 `Port`→`P` 규칙 | 포트 이름 테스트가 모든 종류에서 줄어드는 이름을 요구했다 | 테스트 완화 |
| 링크 없는 포트에는 이벤트 없음 | 신호는 나가도 받는 쪽이 없어 추적을 어지럽히기만 한다 | `NO_LINK` 폐기를 포트마다 기록 |

## 7. 남은 일과 다음 Task에 전할 것

- 허브에는 CLI가 없다 — 터미널을 열면 `HUB1>` 프롬프트에 모든 명령이 "알 수 없는 명령"이다. Cisco Packet Tracer의 허브도 설정이 없어 이 동작이 의도다. 최소 `show` 명령이 필요하면 `DEFINITIONS_BY_KIND.hub`를 채우면 된다
- 허브는 `startRun`을 쓰지 않는다 — 타이머·동적 상태가 없어 `startModels`에 등록하지 않았다
