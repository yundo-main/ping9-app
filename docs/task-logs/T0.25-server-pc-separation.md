## 1. 목표와 완료 기준

T0.23에서 서버는 `kind: "server"`가 됐지만 코드는 `isPcLikeDevice`로 PC와 묶여 있었다.
"PC를 복사해서 서버로 별도로 만든다"는 요구에 따라 PC 코드를 전부 복사해 서버 전용으로 독립시킨다.

- [x] `ServerConfig` 독립 타입과 `ServerDevice`가 `PcConfig`·`PcDevice`를 참조하지 않는다
- [x] `pc/*` 명령은 PC 전용, 서버는 `server/*` 명령 5개 (`server/set-ip`, `server/set-os`, `server/set-service`, `server/add-dns-record`, `server/remove-dns-record`)
- [x] `cli/server/`, `devices/server/`, `reducer/server-*.ts`, `server-console.ts`가 `cli/pc`·`devices/pc`에서 복사된 독립 구현이다
- [x] `isPcKind`·`isPcLikeDevice`·`PcLikeDevice` 공유 헬퍼를 없애고 `isPcDevice`·`isServerDevice`로 분리한다
- [x] 공통 완료 조건 (lint, 타입 검사, 단위 테스트, 빌드, 리뷰)

## 2. 진행 방식

1. shared: `ServerConfig`(`os?: "server"`만 허용)와 `ServerDevice`, `isPcDevice`·`isServerDevice` 가드, `server/*` Command 타입, `ServerView`를 추가했다. `isPcKind`/`isPcLikeDevice`/`PcLikeDevice`는 삭제.
2. engine: `cli/pc` → `cli/server`, `devices/pc` → `devices/server`, `reducer/pc-*` → `reducer/server-*`를 물리 복사한 뒤 이름과 kind 검사를 바꿨다. 서버는 Linux뿐이라 Windows 명령어 목록과 OS 분기는 사본에서 뺐다.
3. engine 원복: `cli/pc`의 서버 전용 구역(`SERVER_ONLY_COMMANDS`, iptables 파일, `hasServerCommands`)과 `devices: ["pc","server"]` 필터를 PC 전용으로 되돌렸다. `pc/set-os`는 이제 `os === "server"`일 때만 `kind`를 `server`로 바꾼다. `server/set-os`는 반대로 `windows`/`linux`를 받아 `kind: "pc"`로 되돌린다.
4. `console.ts`는 PC 콘솔로 되돌리고 서버는 `serverOf()`가 돌려주는 `server-console.ts`의 독립 콘솔이 받는다. `runtime.ts`는 `servers: Map<string, ServerModel>`을 따로 들고 라운드·교환·ARP·뷰 채우기를 PC와 별도로 돌린다. `DeviceView`에 `ServerView`(`kind: "server"`)를 추가해 `computeViews`가 서버 뷰를 낸다.
5. web: `server-address.ts`·`server-settings.tsx`를 `pc-address.ts`·`pc-settings.tsx`에서 복사해 `server/*` 명령을 dispatch한다. `server-services.tsx`는 `server/set-service`·`server/*-dns-record`를 낸다. 나머지 `isPcLikeDevice` 사용처는 `kind === "pc" || kind === "server"` 명시 비교로 바꿨다.
6. 테스트: 서버 대상 `pc/*` 호출을 `server/*`로 갱신하고, `cli/pc`에 있던 `services.test.ts`·`server-iptables.test.ts`를 `cli/server`로 옮겼다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `ServerConfig.os`를 `?: "server"`로 유지 | 저장 파일 호환: 옛 필드·값이 그대로 읽히고 `osOf`·`servicesOf` 같은 config 헬퍼가 구조적으로 그대로 동작 | `os` 칸 제거 — 마이그레이션·헬퍼 전면 수정 필요 |
| `pc/*` 서비스 명령 잔존 | `pc/set-service` 등은 PC에선 언제나 `PC_NOT_SERVER`/`DEVICE_KIND_MISMATCH`로 거절된다. 하위 호환으로 남김 | pc 서비스 명령 삭제 — 불필요한 스키마 변경 |
| `firewall/*` Command는 범용 유지 | 서버·라우터 둘 다 쓰는 규칙 조작 명령이라 `server/` 접두어를 붙이지 않았다 | `server/add-rule` 등 복사 — 같은 동작의 중복 |
| 서버는 OS 선택 칸이 없고 PC 라디오도 windows/linux뿐 | 서버는 팔레트에서 골라 놓는 장비라 OS 선택이 불필요. kind 전환은 `pc/set-os`·`server/set-os` 명령에만 남김 | 라디오로 kind 전환 — 모델이 애매해짐 |
| `device/add`의 옛 형식(`kind:"pc"+os:"server"`) 유지 | T0.23에서 넣은 마이그레이션 경로. 예전 저장·테스트 호출이 그대로 서버를 만든다 | 즉시 제거 — 불필요한 파괴 변경 |

## 4. 계획과 달라진 점

- 계획 문서에 없는 정리 작업이다. T0.23이 "서버를 별도 kind로"였다면 T0.25는 "서버 코드를 PC에서 완전히 복사·분리"다.
- `server/set-os`는 계획에 없는 신규 명령이다: 서버→PC 복귀 전용.
- `firewall/*`는 서버 전용이 아니라 그대로 둔다 (위 결정 표).
