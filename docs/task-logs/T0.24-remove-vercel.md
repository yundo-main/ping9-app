## 2. 진행 방식

1. `git remote set-url`로 origin을 `TL-cg11/PING9`에서 `yundo-main/ping9-app`으로 바꾸고 `main`을 push했다 — 커밋 이력은 그대로 간다.
2. 저장소 안의 Vercel 연동 재료는 `vercel.json` 하나뿐이었다. 지우면 끝 — Vercel 대시보드의 프로젝트 `ping9`은 옛 저장소(`TL-cg11/PING9`)에 연결돼 있으므로 이 저장소에서는 어차피 배포가 일어나지 않는다.
3. 코드에 `DATABASE_URL`을 실제로 쓰는 곳이 없었다(`apps/api`는 자리표시). Neon DB는 Vercel 운영 환경 전용이었으므로 함께 정리 대상이 됐다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `check-secrets.mjs`의 `.vercel/`·Neon 패턴은 남긴다 | 누군가 `vercel link`를 로컬에서 돌려도 비밀값이 커밋되지 않게 막는 방어 규칙 — 연동과 무관하게 해롭지 않다 | 패턴도 같이 제거 |
| 과거 작업 로그(T0.1, T0.4 등)의 Vercel 기술은 고치지 않는다 | 당시 사실의 기록이다. 현재 상태는 CLAUDE.md가 담당 | 로그까지 소급 수정 |
| 운영 주소 `ping9.vercel.app`는 방치 | 옛 저장소에 연결된 Vercel 프로젝트의 일 — 대시보드에서 프로젝트를 지우면 내려간다. 이 저장소에서 할 수 있는 일이 아니다 | — |
| `.github/`(CI)는 유지 | 삭제를 시도했다가 되돌렸다 — push할 때마다 서버에서도 검사되는 안전망이 무료로 붙는다 | CI 제거 (시도 후 철회) |

## 3. 변경 내용

| 파일 | 변경 |
|---|---|
| `vercel.json` | **삭제.** 프레임워크·빌드 명령·출력 디렉터리 설정 — 이 파일이 있으면 Vercel이 이 저장소를 배포 대상으로 본다 |
| `.github/workflows/ci.yml` | "배포는 Vercel이 한다" 주석을 desktop-release 스크립트 안내로 교체. 이후 파일 삭제를 시도했다가 되돌려 **유지** — 혼자 개발이어도 push 검사를 남기기로 함 |
| `.claude/` | **gitignore 처리.** 개인 도구 설정(bmad 스킬 224개 파일)을 추적에서 뺐다 — 로컬 파일은 유지 |
| `scripts/check-secrets.test.mjs` | 허용 파일 예시에서 `vercel.json`을 빼고 `deploy/README.md`로 |
| `CLAUDE.md` | 저장소 주소를 `yundo-main/ping9-app`으로, 배포를 "Tauri 데스크톱 앱, `pnpm desktop:release`"으로, DB를 "없음"으로 갱신. 달라진 결정 절에 T0.24 언급 추가 |
| git remote | `origin` → `https://github.com/yundo-main/ping9-app.git`, `main` push 완료 |
