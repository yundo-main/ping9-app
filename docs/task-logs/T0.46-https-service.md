# T0.46 — 서버에 HTTPS 서비스 추가

## 한 일

서버 장비의 서비스 목록에 HTTPS(tcp/443)를 추가했다. 다섯 번째 서비스로, `SERVICE_KINDS`에서 http 바로 뒤에 둔다.

- `shared/document.ts`: `SERVICE_KINDS`에 `"https"`, `SERVICE_PORTS.https = { tcp, 443 }`.
- `engine/devices/server/services.ts`: 응답은 `http`와 같은 문서를 낸다 — **TLS 핸드셰이크·암호화는 시뮬레이션하지 않는다**. 443 포트에서 HTTP와 같은 요청/응답이 오간다 (교육용 단순화; `servicesOf` 기본값에도 포함돼 새 서버는 https가 켜져 있다).
- `cli/pc/service-commands.ts`, `cli/server/service-commands.ts`: `curl` 주소에 `https://` 방식을 받는다(기본 포트 443). `systemctl start|stop|status https`와 `ss -tuln`의 443 LISTEN도 된다. PC용 파일과 서버용 파일이 같은 코드를 두 벌 갖고 있어 둘 다 고쳤다.
- `server-services.tsx`: 패널에 "HTTPS tcp/443" 스위치.
- `help-dialog.tsx`: 서비스 문구를 "DNS·HTTP(S)"로.

## 계획과 달라진 점

계획 문서에는 없는 기능 추가다. TLS를 흉내내지 않기로 한 것은 명시적 결정 — 인증서·핸드셰이크를 그리려면 프레임 계층이 더 필요하고, 지금 범위에서는 포트와 서비스 구분만 보여주는 것이 맞다고 판단했다.

## 결과

`curl https://<서버>/`가 443으로 가서 문서를 받고, 추적·이벤트는 `HTTPS`로 표시된다. `systemctl stop https`를 하면 443은 거절되고 http는 그대로 동작한다.

## 검증

- `pnpm check`: shared 470 / engine 1895(+1) / web 645 전부 통과.
- 새 테스트: `services.test.ts`의 "HTTPS는 443 포트에서 HTTP와 같은 문서를 준다" — 응답, 추적 service=https, 끄면 Connection refused.
