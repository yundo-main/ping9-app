공통 조작

  • 배치 — 왼쪽 팔레트에서 장비를 캔버스로 끌어 놓습니다. 스위치·라우터 버튼에 마우스를 올리면 종류를 고르는 플라이아웃이 뜹니다.
  • 연결 — 팔레트의 케이블 도구를 켜고 장비 두 대를 차례로 누릅니다.
  • 콘솔 — 장비를 더블클릭하거나, 속성 패널의 터미널 열기를 누릅니다. (허브는 콘솔이 없습니다)
  • 설정 — 장비를 누르면 오른쪽 속성 패널에 이름·IP·서비스 같은 설정이 뜹니다.
  • 편집 — ⌘Z 실행취소 · ⇧⌘Z 재실행 · 범위 선택(선택 도구 또는 Shift+드래그) · File 메뉴에서 새 토폴로지/가져오기/내보내기.
CLI에서 명령은 줄여 쳐도 됩니다 (en→enable, conf t→configure terminal, int gi0/0→interface GigabitEthernet0/0). ?를 치면 그 자리에 올 수 있는 명령을 보여줍니다.

PC

네트워크의 끝점. ping·웹 요청 같은 통신을 시작하는 단말입니다.

속성 패널

  • 이름, IP 주소, 서브넷 마스크, 기본 게이트웨이
  • OS — Windows 또는 Linux. 콘솔 명령이 달라집니다
  • 포트(Ethernet0) 켜기·끄기

주요 명령

주소 확인·설정ipconfig · ipconfig /allip addr · ifconfig eth0
경로 표route printip route · route -n · ip route add default via <IP>
연결 확인ping <IP> · ping -n 4 <IP> · tracert <IP>ping -c 4 <IP> · traceroute -n <IP>
ARParp -a · arp -d *ip neigh · ip neigh flush all

원격 접속ssh <IP> · ssh -l <사용자> <IP> · ssh <사용자>@<IP> — 비밀번호를 묻고, 들어가면 원격 장비의 콘솔이 됩니다. exit로 돌아옵니다

예시

user@PC1 ~ $ ping -c 3 10.0.2.10
user@PC1 ~ $ curl http://10.0.2.10/index.html
user@PC1 ~ $ ssh admin@10.0.2.1

Server

HTTP·DNS·FTP·NTP·SSH 서비스를 돌리는 장비. 겉은 PC와 비슷하지만 서비스 설정이 붙습니다. 콘솔은 Linux입니다.

속성 패널 — 서비스

  • 서비스 스위치 — HTTP(80)·HTTPS(443)·DNS(53)·NTP(123)·FTP(21)·SSH(22)를 개별로 켜고 끕니다
  • DNS 이름 — 이름→주소 레코드를 추가·삭제합니다 (다른 장비의 nslookup이 여기를 묻습니다)
  • 파일 — HTTP·FTP가 내놓는 파일(이름+내용). 비우면 /는 404입니다
  • NTP — stratum(계층) 1–15
  • SSH 계정 — 접속할 수 있는 사용자·비밀번호 (기본 user/ping9)

주요 명령

  • systemctl start|stop|status <서비스> — 서비스를 켜고 끕니다. sshd·httpd 같은 흔한 데몬 이름도 됩니다
  • ss -tuln — 열린 포트 확인 (:80 :22 …)
  • SSH 계정은 속성 패널에서 관리합니다 (콘솔의 useradd는 리눅스 라우터 전용입니다)
  • 주소·경로·링크·파일 명령과 ping·traceroute·curl·nslookup·ssh는 PC(Linux)와 같습니다

Hub L1

물리 계층 장비 — 한 포트로 들어온 비트를 다른 모든 포트로 그대로 내보냅니다.

  • 설정할 것이 없습니다 — 주소도, 콘솔도 없습니다. 포트는 Port0–Port7 여덟 개
  • 모든 포트가 하나의 충돌·브로드캐스트 영역입니다. 스위치와 비교해 흐름을 볼 때 씁니다

Switch (L2) L2

MAC 주소를 배워 프레임을 목적지 포트로만 보내는 2계층 스위치. VLAN으로 네트워크를 나눕니다. 포트는 FastEthernet0/1–0/8 여덟 개입니다.

콘솔 — Cisco IOS 형식

SW1> enable
SW1# configure terminal
SW1(config)# vlan 10                 ← VLAN 생성
SW1(config-vlan)# name SALES
SW1(config)# interface fa0/1
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10   ← 포트를 VLAN 10에
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk allowed vlan add 10-20

확인 명령

  • show vlan brief — VLAN과 포트 배정
  • show mac address-table — 배운 MAC과 포트
  • show interfaces trunk — 트렁크 포트와 허용 VLAN
  • show running-config — 전체 설정
서로 다른 VLAN의 장비는 직접 통신하지 못합니다 — 라우터나 L3 스위치가 필요합니다.

L3 Switch L3

L2 스위치의 기능 위에 라우팅을 얹은 장비. VLAN 사이를 직접 잇습니다 (SVI).

L2 명령

vlan·switchport·show vlan brief 등 L2 스위치와 같습니다.

L3 명령

L3SW1(config)# ip routing                    ← 라우팅 켜기
L3SW1(config)# interface vlan 10              ← VLAN 10의 SVI
L3SW1(config-if)# ip address 192.168.10.1 255.255.255.0
L3SW1(config-if)# no shutdown
L3SW1(config)# interface fa0/8
L3SW1(config-if)# no switchport               ← 라우티드 포트로
L3SW1(config-if)# ip address 10.0.0.1 255.255.255.0
  • show ip route — 라우팅 표 (SVI·라우티드 포트의 connected 경로 포함)
  • show ip interface brief — 인터페이스별 주소·상태

Load Balancer L4/7

HAProxy 형식의 로드밸런서. 들어온 요청을 여러 백엔드 서버로 나눕니다 — 백엔드의 응답도 LB를 거칩니다(DNAT). 포트는 eth0·eth1 두 개입니다.

설정 (속성 패널)

  • 인터페이스(eth0·eth1) IP — 앞단·뒷단 네트워크를 잇습니다
  • 정적 경로
  • 프런트엔드 — 받는 포트, 방식(tcp=L4 전달 / http=L7 프록시), 백엔드 목록(IP·포트·가중치, http 모드는 경로 접두로 배분 가능)

콘솔 — Linux + HAProxy

  • cat /etc/haproxy/haproxy.cfg — 설정이 실제 설정 파일 모양으로 보입니다
  • haproxy -c — 설정 검사
  • ip addr·ip route·ip neigh·ping·hostname

Router

서로 다른 네트워크를 잇는 3계층 장비. 배치할 때(또는 속성 패널에서) CLI 형식을 고릅니다 — IOS · VyOS · Linux. 포트는 네 개 — IOS에선 GigabitEthernet0/0–0/3, Linux·VyOS에선 eth0–eth3으로 보입니다.

IOS 형식 (Cisco)

R1> enable
R1# configure terminal
R1(config)# interface gi0/0
R1(config-if)# ip address 10.0.1.1 255.255.255.0
R1(config-if)# no shutdown
R1(config)# ip route 10.0.3.0 255.255.255.0 10.0.2.2   ← 정적 경로
R1(config)# router rip                              ← RIP 경로 교환
R1(config-router)# network 10.0.0.0
  • 루프백 — interface loopback0로 만들고 /32 주소를 줍니다. no interface loopback0로 지웁니다 (최대 Loopback0–3)
  • 터널·VPN — interface tunnel0 + GRE, crypto isakmp/ipsec 계열로 IPsec
  • SSH — ip domain-name <이름> → username <u> secret <p> → crypto key generate rsa. 순서가 실제와 같습니다
  • 확인 — show ip route · show ip interface brief · show running-config · show ip ssh · ping·traceroute

VyOS 형식

vyos@R1:~$ configure
vyos@R1# set interfaces ethernet eth0 address 10.0.1.1/24
vyos@R1# set protocols static route 10.0.3.0/24 next-hop 10.0.2.2
vyos@R1# set service ssh
vyos@R1# commit ← 커밋해야 적용됩니다
  • set으로 올리고 delete로 내립니다. commit 전엔 적용되지 않고, config 모드의 show가 후보 설정을 보여줍니다. 버리려면 discard 또는 exit discard
  • NAT(set nat source/destination rule …)·GRE 터널(interfaces tunnel tun0)·IPsec(vpn ipsec …)·SSH 계정(system login user)도 set 경로로 합니다
  • 운영 명령(show interfaces·show ip route·ping 등)은 운영 모드(~$)에서 치고, config 모드에선 run <명령>으로 씁니다

Linux 형식

root@R1:~# ip addr add 10.0.1.1/24 dev eth0
root@R1:~# ip link set eth0 up
root@R1:~# ip route add 10.0.3.0/24 via 10.0.2.2
root@R1:~# sysctl -w net.ipv4.ip_forward=1   ← 전달 켜기
  • ip addr·ip route·ip link·ip neigh — 일반 Linux 그대로
  • sysctl -w net.ipv4.ip_forward=1 — 라우팅(전달)을 켭니다. 꺼져 있으면 경유하지 않습니다
  • iptables -t nat … — NAT(MASQUERADE·SNAT·DNAT)
  • useradd <u> -p <비밀번호> + systemctl start ssh — SSH 켜기
라우터 주소로 온 패킷은 라우터가 자기 자신에게 온 것으로 받습니다 — 열린 서비스(SSH·NTP 없음)가 없으면 거절됩니다.

Cloud WAN

가상의 인터넷 — 1.0.0.0/8을 /30으로 자른 라우터 망이 안에 들어 있다고 보는 장비입니다.

  • 포트는 Port0–Port3 네 개. 순번 i의 포트에는 1.0.0.{4i}/30 링크망이 고정 배정됩니다 — 클라우드 쪽이 .{4i+1}, 붙는 장비가 .{4i+2}
  • 붙는 장비(주로 라우터)의 인터페이스를 그 포트의 .{4i+2}/30로, 경로의 다음 홉을 .{4i+1}로 잡으면 포트 사이를 라우팅해 줍니다 — 어느 포트의 상대 주소든 목적지가 되면 그 포트로 전달
  • 설정과 콘솔이 없습니다 — 허브처럼 배치만 하면 됩니다. 인스펙터에 포트별 링크망이 보입니다
  • 클라우드 포트 주소(.{4i+1})로의 ping에는 직접 응답하고, TTL을 줄여 전달합니다 — traceroute에서 한 홉으로 보입니다
예: R1 gi0/0 ── Cloud Port0     R2 gi0/0 ── Cloud Port1
R1(config)# ip address 1.0.0.2 255.255.255.252    ← Port0의 상대 주소
R1(config)# ip route 192.168.2.0 255.255.255.0 1.0.0.1   ← 클라우드 쪽이 다음 홉
R2(config)# ip address 1.0.0.6 255.255.255.252    ← Port1의 상대 주소
라우터끼리 클라우드를 경유할 때는 각자가 자기 포트의 /30 상대 주소를 쓰고, 다른 쪽 네트워크로 가는 정적 경로의 다음 홉을 자기 포트의 클라우드 주소(.{4i+1})로 잡습니다.
